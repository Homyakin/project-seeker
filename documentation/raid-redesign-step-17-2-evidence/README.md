# Материалы общей калибровки походов 17.2

[Результат и ограничения](../raid-redesign-step-17-2-raid-calibration.md), [первоначальные условия и последующее согласование](protocol.md), [принятые значения](accepted-selection.json).

## Две сохранённые версии условий

Первоначальное исследование: `screen/`, 825 условий / 16 500 боёв. Строгое требование 45–55% не прошло у волков: 373/660 побед при `0,75`, примерно 57%. Это сохраняется как отрицательный результат в `screen-validation.json` и исходной сводке. Код завершения первоначальной проверки — 2 из-за критерия, не технической ошибки исходных строк.

После явного ответа пользователя «соседняя — 57% - сойдет» приняты уже измеренные ближайшие значения без нового исследования. `accepted-selection.json` фиксирует карту и технический допуск подтверждения: волки 45–60%, остальные 45–55%. Число 60% — заранее заданный исполнителем допуск около одобренных 57%, не буквальная цитата пользователя. Первоначальные результаты и отказы не переписаны.

`screen-sources.tar.gz` содержит четыре прежних генератора и пять их технических тестов. `screen-additional-test.tar.gz` — прежний интеграционный тест миконидов. `screen-study-sources.tar.gz` — первоначальные исполнитель, его тест, проверяющий, протокол и отдельная историческая утилита. Эти снимки соответствуют контрольным суммам исходной предварительной фазы, а не новой версии после согласования. Для воспроизведения именно первоначального исследования нужна отдельная сборка этих версий; нынешние файлы не подставляются под старые суммы.

Первый `screen-plan-attempt-1` был подготовлен до последней правки проверяющего, боёв в нём нет; актуальная фаза `screen` спланирована заново до боёв. Первый `final-plan-attempt-1` также не исполнялся: полная сборка выявила ожидание прежнего коэффициента V3 в интеграционном тесте миконидов. После точечного исправления `0,77→0,82` прежняя попытка/журнал сохранены, чистая сборка и окончательное планирование повторены. Историческое ожидание `0,77` в том же тесте не менялось.

## Первая проверка и команды воспроизведения

Первая проверка — `final/`, 1004 условия / 23 600 боёв. На каждый поход — 33 основных условия L10 по 50 зеркальных пар, остальные семейства раскрываются отдельно. Предварительные исходы не прибавляются к этой независимой выборке. Заранее выбранные 40 условий / 80 полных боёв повторены новым процессом в `replay/`; все строки совпали.

`final-validation.json` корректно имеет отрицательный итог (код завершения 2): зомби при `0,78` дали 43,36%, ниже 45%. Остальные три похода прошли свои условия. Все технические проверки строк/формул/сводок выполнены. Отрицательный общий результат не меняется под последующую правку зомби.

Для воспроизведения именно первой проверки сначала восстановить в **отдельной копии проекта** три исходника из `first-final-zombie-sources.tar.gz` и собрать её: они содержат `0,78`, нынешний код намеренно содержит `0,76`. Старые суммы не сверяются с новыми игровыми источниками. Остальные 226 входов первой проверки сохранены в нынешних путях. Команды ниже исторические, не команда запуска на нынешних классах.

Команды из корня репозитория; `seeker_raid172_classpath` содержит собранные `game/target/test-classes`, `game/target/classes` и зависимости тестов. Каждый новый каталог должен быть отдельным непосредственным потомком этой папки материалов, чтобы проверяющий видел неизменные соседние `screen/`, `screen-validation.json` и `accepted-selection.json`. Вывод не перезаписывается.

```sh
java -Xmx2g \
  -Draid.study.production.WOLFPACK=0.75 \
  -Draid.study.production.ZOMBIE_HORDE=0.78 \
  -Draid.study.production.MYCONID_COLONY=0.82 \
  -Draid.study.production.MAGGEESE_FLOCK=0.725 \
  -cp "$seeker_raid172_classpath" \
  ru.homyakin.seeker.game.battle.Step172RaidCalibrationStudy plan-final NEW_FINAL_DIRECTORY
```

С теми же свойствами выполнить `run-final NEW_FINAL_DIRECTORY`, затем отдельным процессом `replay-final NEW_FINAL_DIRECTORY NEW_REPLAY_DIRECTORY`.

```sh
node documentation/raid-redesign-step-17-2-evidence/validate-study.mjs \
  FINAL NEW_FINAL_DIRECTORY NEW_REPLAY_DIRECTORY NEW_REPORT_JSON
```

Сборка выполняется из `game`: `mvn -o -B -ntp clean package`; в использованной среде заданы JDK 25.0.1 с целью компиляции 24 и явный агент Mockito. Полный журнал — `clean-package.log`, первая неудачная попытка — `clean-package-attempt-1.log`.

`pre-change-classes.tar.gz` содержит пять отдельно сохранённых файлов классов до этой калибровки. Новый `Step172RaidHistoricalCompatibilityStudy` сравнивает с ними **792 исторических условия**, включая характеристики, идентификаторы, инициативу и следующее случайное значение. Он не требует прежних 66 совпадений миконидов V3: этот путь теперь намеренно перенастроен. Старая утилита и все прежние материалы остаются неизменными. Итог — `historical-compatibility.json`.

## Отдельная повторная попытка зомби

Условия — [retry-protocol.md](retry-protocol.md), единственное значение и запрет дальнейшего перебора — [zombie-retry-selection.json](zombie-retry-selection.json). Новый `Step172ZombieConfirmationStudy` проверяет только `0,76` обычным игровым путём: 251 условие / 5900 боёв, новые корни `20261126000000 / 30261126000000`. Никакие исходы первой `0,78` не прибавляются к новой оценке. Ещё до боёв фиксируются исходники/условия в `zombie-retry/protocol.json` и `retry-lock.sha256`.

Команды для нынешней реализации:

```sh
java -Xmx2g -cp "$seeker_raid172_classpath" \
  ru.homyakin.seeker.game.battle.Step172ZombieConfirmationStudy plan-final NEW_RETRY_DIRECTORY
```

Затем с тем же путём классов — `run-final NEW_RETRY_DIRECTORY`, после завершения отдельным процессом — `replay-final NEW_RETRY_DIRECTORY NEW_REPLAY_DIRECTORY`. Повторяются заранее выбранные 10 условий / 20 полных боёв.

```sh
node documentation/raid-redesign-step-17-2-evidence/validate-zombie-retry.mjs \
  NEW_RETRY_DIRECTORY NEW_REPLAY_DIRECTORY NEW_REPORT_JSON
```

Результаты этой попытки: `zombie-retry/`, `zombie-retry-replay/`, `zombie-retry-validation.json`. Новый проверяющий также сверяет прежние 229 исходников: 226 нынешних и три из сохранённого архива, а также связывает исходный отказ и предварительное значение `354/660`. Старые исполнитель/протокол/проверяющий не редактировались ради повторной попытки.

Новый исполнитель и девять его тестов первоначально не скомпилировались из-за пропущенного списка размеров; до боёв он возвращён в точности. Первая попытка сохранена в `retry-matrix-tests.log`, успешная — `retry-matrix-tests-attempt-2.log`. Полная чистая сборка после последней игровой правки — `clean-package-zombie-retry.log`, повторная история — `historical-compatibility-zombie-retry.json`.

Новая отдельная попытка подтверждена: зомби `1814/3300 = 54,97%`, полоса прежняя 45–55%, без незавершений/ошибок. Независимый проверяющий завершился с кодом 0; все 20 полных повторных строк совпали. Это не отменяет прежний отрицательный `final-validation.json`. Нынешний итог остальных трёх походов берётся из их прежней успешной части: волки 56,15%, микониды 53,85%, маггуси 47,48%. Дальнейшего подбора нет. Чистая сборка — 1950 тестов, 29 прежних пропусков, без ошибок; 792 исторических сравнения повторно совпали.

Последними выполнены независимые [балансовый](independent-review-balance.md) и [технический](independent-review-technical.md) разборы. Препятствий ограниченному закрытию нет; слабые основные одиночки/большие группы, сильные бесплатные направления, верхние уровни и длительность раскрыты. После этого анализа игровые исходники и бои не менялись. Все 13 прежних наборов материалов повторно проверены: `previous-artifacts-validation-after-retry.json`.

## Проверки сохранности

`screen-lock.sha256` относится к первоначальным версиям, которые после явного согласования и игровой правки надо проверять по архивам, а не по нынешним файлам. `final-lock.sha256` фиксирует условия первой проверки до её боёв; они сохранены неизменно. `retry-lock.sha256` — условия новой попытки до её боёв. `inputs.sha256` и `artifacts.sha256` относятся к текущим публичным входам и сохранённым результатам. Сжатые исходные строки следует читать потоком.

Проверяющий независимо вычисляет мощь из предметов и основы противников, цели с единственной поправкой, общую случайность предварительных вариантов, все сводки/сравнения и целевую долю побед. Повторные строки сравниваются целиком, без удаления полей. Только ключи отображений и настоящие множества слотов канонизируются; порядок участников/предметов/атак/событий сохраняется.

Это не запуск бота, не применение к рабочей БД, не начисление наград и не включение выпуска. Экономическая безопасность и доступность каждого уровня/состава не выводятся из одной средней доли побед.
