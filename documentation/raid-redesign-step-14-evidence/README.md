# Проверочные данные шага 14

Это проверка общей основы подбора и воспроизводимости `V3` против `V3`, **не приёмка баланса отдельных походов**. Решения и ограничения — в [отчёте](../raid-redesign-step-14-common-pve.md).

## Состав

- `run/battles.jsonl.gz` — 4176 записей настоящих боёв, с полными входами, результатом подбора и начальным снимком. Полный журнал и подробная последовательность действий представлены контрольными суммами и воспроизводятся из входов, а не сохранены повторно в каждой записи.
- `run/summary.json` — 696 условий, по три пары с обратным порядком сторон.
- `validation-replay.json` — проверка данных и совпадения независимого запуска Java.
- `sources.tar.gz` — явно выбранные общедоступные исходники, необходимые для фиксации входов исследования; основа — коммит `bd142e61a0aa2fc0e1b2117164ab4bc6fac29469` плюс сохранённые файлы. Это не полный независимый дистрибутив проекта.
- `inputs.sha256`, `selected-inputs.txt` — контрольные суммы и точный список выбранных файлов.
- `environment.json`, `test-summary.json` — среда и результаты сборки.
- `artifacts.sha256` — контрольные суммы сохранённых данных и архива исходников.
- `validate-study.cjs` — потоковая проверка записей, уникальности запусков, размеров составов, прежних коэффициентов, версий, подготовки предметов, согласованности итогов и повтора.

Секретные настройки разработки, рабочая БД, содержимое `target` и постороннее изменение проверки блокировок в снимок не включены. Материалы шага 13 не изменялись.

## Проверка сохранённых данных

Нужен Node.js; использовался 24.22.1. Из корня репозитория:

```sh
node documentation/raid-redesign-step-14-evidence/validate-study.cjs documentation/raid-redesign-step-14-evidence/run
sha256sum -c documentation/raid-redesign-step-14-evidence/inputs.sha256 --quiet
```

Проверка `inputs.sha256` выполняется из корня зафиксированной копии проекта; после дальнейших правок исходников она закономерно обнаружит расхождения. Проверка `artifacts.sha256` выполняется из каталога этих проверочных данных. В архиве выбранные исходники расположены под `source/`; список и суммы относятся к путям относительно этого каталога.

Ожидаются 696 условий, 4176 боёв, 2658 побед участников и 1518 поражений, без ничьих и незавершения; максимум 129 тактов. Контрольная сумма распакованного потока записей — `a017da45c08622a9b16aba91264e71c5a38afc7d10118493360efa5f7a883bee`.

Эти суммарные исходы не задают желаемую долю побед: выборка намеренно смешивает разные уровни, численность и составы. По три пары на условие недостаточно для выводов о его балансе. Обе ветви количества противников при двух игроках аномалии встречаются в 20 из 24 соответствующих условий и в выборке в целом, не во всех 24 условиях.

## Повтор

В проверенной копии исходников собрать модуль, не запуская приложение. Рабочая БД и Telegram не нужны. Если среда требует явный агент `Mockito`, добавить его в `JAVA_TOOL_OPTIONS`, как при полной сборке этого шага.

```sh
cd game
mvn test -Dtest=PveCharacteristicScalingTest,PveAdaptationStudyTest,RaidNpcCombatVersionTest,RaidProcessingCombatVersionTest,AnomalySafePveGeneratorTest,AnomalyBattleServiceCombatVersionTest
mvn dependency:build-classpath -Dmdep.outputFile=/tmp/seeker-step14-classpath.txt
java -Xmx768m -Dpve.study.boundaries=true -Dpve.study.pairs=3 \
  -cp "target/test-classes:target/classes:$(cat /tmp/seeker-step14-classpath.txt)" \
  ru.homyakin.seeker.game.battle.PveAdaptationStudy /tmp/seeker-step14-new-run
```

Каталог результата должен отсутствовать до запуска; существующие данные не перезаписываются. Новый запуск Java с другим новым каталогом повторяет исследование независимо. После этого из корня репозитория:

```sh
node documentation/raid-redesign-step-14-evidence/validate-study.cjs \
  documentation/raid-redesign-step-14-evidence/run /tmp/seeker-step14-new-run
```

Повтор обязан совпасть целиком, включая контрольные суммы действий. Источники случайности генерации и боя разделены; начальные числа и порядок сторон есть в каждой записи. Вторая копия 4176 боёв не хранится рядом с первой и не считается дополнительной независимой выборкой.

## Что здесь не проверяется

Безопасная аномалия и замена группового боя используют один генератор. Их оба настоящих вызова проверены в `AnomalyBattleServiceCombatVersionTest`; две метки стенда не означают два независимых алгоритма. Проверка выплат, повторного завершения и PostgreSQL предусмотрена шагом 19. Исправление дальностей, скачков поправок численности и настройка силы событий — шаги 15–19. Включение выпуска не выполнялось.
