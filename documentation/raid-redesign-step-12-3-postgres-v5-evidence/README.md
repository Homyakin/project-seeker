## Содержимое

`verification.tar.gz` содержит журналы целевого запуска и полной сборки, краткие результаты JUnit, отобранные исходники и игровые данные, перечень входов и их SHA-256. `verification.sha256` проверяет архив. Секретный `application-dev.properties`, полный каталог ресурсов и полные свойства окружения JUnit в архив не включены.

Первый подготовительный запуск не скомпилировался из-за обращения нового теста к непубличному `usesScalingCombatRules()`. Обращение удалено без расширения производственного API; неуспешный журнал сохранён отдельно и не выдаётся за выполненные сценарии БД. Следующий целевой запуск выполнил все 15 сценариев без ошибок и пропусков.

Окончательный `mvn clean package` завершился успешно за 2 минуты 37 секунд: **1 512 учтённых тестов, 1 493 успешно выполнены, 19 намеренно пропущены**, ошибок и нарушений Checkstyle нет. Новый класс: **15/15**, прежний PostgreSQL-класс: **9/9**, без пропусков. Целевые 15 не прибавляются к итогу полной сборки второй раз.

Все проверочные схемы удалены тестами; после фиксации результатов контейнер удалён. Уничтожены только воспроизводимые синтетические данные опыта. Образ PostgreSQL сохранён.

Полная сборка выполнялась в существующем рабочем дереве. Ранее имевшееся постороннее изменение `InMemoryLockServiceTest` не редактировалось и не включено в снимок исходников этой задачи. Результат полной сборки относится к фактически проверенному дереву; отдельные целевые 15 сценариев от этого теста не зависят.

## Воспроизведение

Из корня проекта, при свободном порте и отсутствии контейнера с указанным именем:

```bash
docker run --detach --pull=never --name seeker-step123-v5-nov07 \
  --label seeker.audit=step123-v5-nov07 --publish 127.0.0.1:55435:5432 \
  --tmpfs /var/lib/postgresql/data:rw,size=512m \
  --env POSTGRES_DB=seeker_step123_v5_nov07 --env POSTGRES_USER=dev --env POSTGRES_PASSWORD=dev \
  postgres@sha256:9e2cf6287f25c3151f4c9421ccce2b17f3e60061c111a29165e0d2cdd9ff0a97

docker exec seeker-step123-v5-nov07 pg_isready -U dev -d seeker_step123_v5_nov07
```

После готовности, из `game/`:

```bash
env JAVA_HOME=/home/user/.jdks/axiomjdk-25.0.1 \
  JAVA_TOOL_OPTIONS=-javaagent:/home/user/.m2/repository/org/mockito/mockito-core/5.18.0/mockito-core-5.18.0.jar \
  SEEKER_POSTGRES_TEST_URL=jdbc:postgresql://127.0.0.1:55435/seeker_step123_v5_nov07 \
  SEEKER_POSTGRES_TEST_USER=dev SEEKER_POSTGRES_TEST_PASSWORD=dev \
  /opt/apache-maven-3.9.12/bin/mvn test -Dtest=EquipmentReleasePostgresIntegrationTest
```

Для полной проверки тот же набор переменных передаётся `mvn clean package`. Без `SEEKER_POSTGRES_TEST_URL` классы проверок PostgreSQL намеренно пропускаются; такой запуск не заменяет настоящую проверку БД. В ограниченной среде может требоваться разрешение на соединение с локальной БД.

После завершения удаляется **только собственный проверочный контейнер**, предварительно сверенный по имени, идентификатору и метке:

```bash
docker inspect seeker-step123-v5-nov07 --format '{{.Id}} {{index .Config.Labels "seeker.audit"}}'
docker rm --force seeker-step123-v5-nov07
```

Удаление уничтожает только временные синтетические данные; они восстанавливаются повторным запуском тестов. Образ и пользовательские БД не удаляются.
