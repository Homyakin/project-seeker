# Свидетельства адаптации обычных походов, шаги 16–18

Дата: 2026-11-15. Здесь сохранена ограниченная проверка новой боёвки Волчьей стаи, Орды зомби и Стаи маггусей. Человеческий итог и решение о закрытии находятся в [общем отчёте](../raid-redesign-steps-16-18-raids.md); этот файл — указатель исходных свидетельств и инструкция повторения.

## Что выполнено

До боёв записаны [условия проверки](protocol.md), полный протокол с предметами/начальными значениями и [контрольные суммы до запуска](pre-run-lock.sha256). Замороженный протокол содержит **220 публичных исходников**. Их соответствие текущим файлам, независимая арифметика мощности/целей/окончательных фабрик, сводки и все парные сравнения проверены отдельным исполнителем.

Выполнены **1044 заранее заданных условия / 18480 боёв** и ещё **68 заранее выбранных повторных боёв новым процессом**. Все бои завершены, ошибок и незавершений нет; все 68 повторных строк совпали по всем полям JSON. При сравнении порядок ключей отображений несущественен, но значимые массивы не переставляются. Только настоящие множества слотов канонизированы исполнителем до записи.

Чистая сборка `game`: **1919 учтённых проверок, 1890 успешно, 29 прежних/условных пропусков, 0 ошибок и отказов, 0 нарушений Checkstyle**. Среди них семь проверок матрицы и канонизации нового исполнителя. Отдельное двоичное сравнение с прежними классами, сохранёнными до первой перекомпиляции: **792 исторических условия и 66 условий миконидов V3, всего 858 совпадений**, включая характеристики, диагностику, идентификаторы, инициативу и последующее случайное значение. Оно не подменяет боевые проверки новых походов.

## Проверка сохранённых свидетельств

Команды выполняются из корня репозитория. Отчёт проверяющего должен иметь **новый** путь: существующий файл не перезаписывается.

```sh
cd /home/user/projects/project-seeker
sha256sum -c documentation/raid-redesign-steps-16-18-evidence/pre-run-lock.sha256
sha256sum -c documentation/raid-redesign-steps-16-18-evidence/inputs.sha256
sha256sum -c documentation/raid-redesign-steps-16-18-evidence/artifacts.sha256

RAID_STUDY_WORK=$(mktemp -d /tmp/seeker-raids-recheck.XXXXXX)
/home/user/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node \
  --max-old-space-size=2048 \
  documentation/raid-redesign-steps-16-18-evidence/validate.mjs \
  documentation/raid-redesign-steps-16-18-evidence/run \
  documentation/raid-redesign-steps-16-18-evidence/replay \
  "$RAID_STUDY_WORK/independent-validation.json"
```

Проверяющий читает JSONL через поток распаковки и построчный разбор. Не распаковывать весь большой журнал в строку/буфер памяти; для ручного разбора использовать тот же потоковый подход. Если исходники после этой проверки намеренно изменены, несовпадение их сумм ожидаемо и не устраняется переписыванием старого протокола.

## Повторение сборки и боёв на новых путях

В исходной проверке использован `/home/user/.jdks/axiomjdk-25.0.1` при целевой версии проекта Java 24. Mockito подключался явным агентом, как записано в журнале сборки. Maven работал автономно (`-o`) на уже загруженных зависимостях. При любой ошибке сначала остановить повторение и разобраться с причиной.

Следующий пример создаёт только новые результаты во временном каталоге. Сохранённые оригиналы не используются как место вывода. Протокол нового прогона фиксируется **до** его боёв.

```sh
cd /home/user/projects/project-seeker
RAID_STUDY_WORK=$(mktemp -d /tmp/seeker-raids-reproduce.XXXXXX)
(
  cd game
  JAVA_HOME=/home/user/.jdks/axiomjdk-25.0.1 \
  JAVA_TOOL_OPTIONS=-javaagent:/home/user/.m2/repository/org/mockito/mockito-core/5.18.0/mockito-core-5.18.0.jar \
    mvn -o clean package
  JAVA_HOME=/home/user/.jdks/axiomjdk-25.0.1 \
    mvn -o dependency:build-classpath -DincludeScope=test \
    "-Dmdep.outputFile=$RAID_STUDY_WORK/classpath.txt"
)

RAID_STUDY_CP="game/target/test-classes:game/target/classes:$(< "$RAID_STUDY_WORK/classpath.txt")"
RAID_STUDY_JAVA=/home/user/.jdks/axiomjdk-25.0.1/bin/java
"$RAID_STUDY_JAVA" -Xmx2g -cp "$RAID_STUDY_CP" \
  ru.homyakin.seeker.game.battle.Step1618RaidValidationStudy plan "$RAID_STUDY_WORK/run"
"$RAID_STUDY_JAVA" -Xmx2g -cp "$RAID_STUDY_CP" \
  ru.homyakin.seeker.game.battle.Step1618RaidValidationStudy run "$RAID_STUDY_WORK/run"
"$RAID_STUDY_JAVA" -Xmx2g -cp "$RAID_STUDY_CP" \
  ru.homyakin.seeker.game.battle.Step1618RaidValidationStudy \
  replay "$RAID_STUDY_WORK/run" "$RAID_STUDY_WORK/replay"
/home/user/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node \
  --max-old-space-size=2048 \
  documentation/raid-redesign-steps-16-18-evidence/validate.mjs \
  "$RAID_STUDY_WORK/run" "$RAID_STUDY_WORK/replay" "$RAID_STUDY_WORK/independent-validation.json"
```

`plan` создаёт новый каталог; `run` требует неизменившийся протокол и новые файлы результатов; `replay` создаёт другой новый каталог. Исполнитель применяет `CREATE_NEW`, проверяющий — режим `wx`. Повторять команды поверх существующего вывода нельзя. Новое выполнение на другом процессе даёт отдельную проверку воспроизводимости, а не дополнительные независимые наблюдения для старых процентов.

### Двоичное сравнение с прежними генераторами

После сборки и формирования `RAID_STUDY_CP` выше распаковать сохранённые пять файлов в **новый** каталог, затем передать утилите новый путь отчёта:

```sh
RAID_STUDY_BASELINE=$(mktemp -d /tmp/seeker-raids-baseline-replay.XXXXXX)
tar -xzf documentation/raid-redesign-steps-16-18-evidence/baseline-classes.tar.gz \
  -C "$RAID_STUDY_BASELINE"
"$RAID_STUDY_JAVA" -Xmx1g -cp "$RAID_STUDY_CP" \
  ru.homyakin.seeker.game.battle.RaidHistoricalCompatibilityStudy \
  "$RAID_STUDY_BASELINE" "$RAID_STUDY_WORK/historical-compatibility.json"
```

Сравнение использует прежние классы только для генераторов, разделяя с текущим кодом модель участника, интерфейс и область случайности. Нормализуются ключи отображений; порядок массивов, состав и порядок создания остаются значимыми. Исходный архив не обновляется по результатам повторения.

## Границы результата

Зеркала внутри пары зависимы. Интервальные оценки по отдельным условиям используют полные пары, а не число зеркальных боёв; они не являются одновременной гарантией всей матрицы. При 5/8/10 парах неопределённость широка. Раунды — не секунды. Отсутствие незавершений подтверждено в этой выборке, не для любого будущего набора предметов.

Не проверяется точное сохранение прежних долей побед; не требуются 50/50, одинаковая сила контртипов, обязательная польза союзника или доступность всех уровней каждой сборке. Принятый штраф за добавление участника не переименовывается в запрещающий критерий. Совокупные победы в разных семействах не доказывают причинное преимущество одного типа защиты или атаки.

Наличие побед с бесплатными предметами на низком уровне не скрывается. Проверка боёв не доказывает стоимость наград, их начисление, транзакции или отсутствие всех экономических обходов. Рабочая БД, приложение, бот, выдача предметов, кривая усиления и включение выпуска не запускались и не перепроектировались этой проверкой. Независимые рецензии имеют собственные указанные области, а не являются авторским самоподтверждением исполнителя боёв.
