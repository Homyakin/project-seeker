Статус: **расширенная версия завершена 2026-09-13**. Спроектирован новый каталог, но игровые `TOML`, код и БД не изменены. До приёмки боевых прогонов на шаге 12 этот каталог и четыре новых модификатора существуют только как проверочные входные данные.

## Итог в кратком виде

- Все 40 существующих добываемых `ItemObject.code` сохраняются, но получают новые числа; случайно подходящих без изменения объектов нет.
- Добавляются два предмета для двух рук и двадцать доспехов: по одному новому варианту каждого типа защиты в каждой из пяти неоружейных ячеек. Итоговый добываемый каталог содержит 62 объекта.
- В корпусе, на ногах, в обуви, на голове и руках становится по восемь предметов: два тканевых, два кожаных, два латных и два зачарованных. Основная и вторая рука этим расширением не меняются.
- Из добычи ничего не выводится. Старый объект не удаляется из `TOML`, поэтому не возникает ложного ожидания, что его строка исчезнет из БД или набора выпадения.
- У арбалета исправляется тип атаки с `BLUNT` на `PIERCE`, у кинжала — с `SLASH` на `PIERCE`. Для дальнобойного оружия атака раскладывается на части с настоящими условиями дистанции.
- Все положительные растущие основы кратны 60. Поэтому утверждённая функция `B₁` даёт видимую целую прибавку на каждом переходе без частных исключений для предметов.
- Предметы не содержат роль, разрешённое умение, основной тип сборки или требования к соседним предметам. Любой предмет по-прежнему может использовать любой игрок.
- Каталог модификаторов расширяется с 11 до 15 записей. Новый общий отбор гарантирует максимум ровно 8 очков каждого умения в физически допустимом полном комплекте.
- Все 105 неупорядоченных пар из 15 разных умений достижимы. Их предзаданные проверки вынесены во [внешнюю матрицу](raid-redesign-step-7-build-matrix.md).
- В любой полной сборке сумма вкладов силы воздействия находится в диапазоне `0…20`, поэтому `L=80…100` и ни один штатный вклад не пропадает за пределом.

## Обозначения таблиц

- `ОСН`, `ВТОР`, `КОРП`, `НОГИ`, `ОБУВЬ`, `ГОЛОВА`, `РУКИ` — основная рука, вторая рука, корпус, ноги, обувь, голова и руки.
- Часть атаки записывается как ``тип:величина@[dmin;dmax]``. Величины частей складываются только на тех дистанциях, где выполнено их собственное условие.
- `H` — здоровье; `D` — тип и величина защиты; `КШ` — шанс критического удара в процентных пунктах; `УКЛ` — уклонение в процентных пунктах.
- `+КУ` — прибавка предмета к базовому множителю критического урона `1,20`; `S` — скорость; `T` — исходная угроза; `l` — вклад силы воздействия.
- Все строки ниже задают состояние `+0`. Усиленные значения здоровья, каждой части атаки и защиты вычисляются функцией шага 5, а остальные столбцы напрямую не растут.

## Соответствие прежнему каталогу

Исходные значения всех 40 строк приведены в [проверке шага 1](raid-redesign-step-1-audit.md). Для каждой из них новая строка с тем же `code` полностью заменяет прежние боевые числа. Ячейки и русские названия добываемых объектов сохраняются; исключений переноса по новому коду нет.

- прежняя одиночная атака становится первой частью с `dmin=1`, после чего у `staff`, `bow` и `longbow` добавляется отдельная условная часть;
- `crossbow` меняет ошибочный `BLUNT` на `PIERCE`, а `dagger` — `SLASH` на `PIERCE`;
- все прежние защита, здоровье, критический удар, уклонение, множитель критического урона, скорость и угроза заменяются значениями таблиц ниже;
- каждому объекту добавляется новый `l`; отсутствие поля в прежней сохранённой версии читается как ноль;
- ни один прежний объект не остаётся неизменным, не меняет занятые ячейки и не выводится из добычи;
- `battle_staff` и `ritual_staff` — новые коды предметов для двух рук; ещё двадцать новых кодов доспехов перечислены в отдельной таблице ниже. Ни один из них не заменяет прежний объект.

Обновление строки по существующему `code` затронет все уже выданные экземпляры. Именно поэтому таблицы не переносятся в действующий `TOML` до проверки и операции шага 11.

Облегчённый латный вариант дополнительно уступает прежнему по здоровью, а бригантина — ещё и по защите: иначе потеря угрозы могла бы оказаться преимуществом почти для любой сборки.

## Горизонтальные альтернативы

Внутри одной ячейки нет скрытой последовательности «плохой предмет → прямое улучшение». Различия должны создавать выбор против соперника и способ действия полной сборки:

| Группа | Основной обмен |
|---|---|
| Меч / булава | одинаковая атака ближнего боя; меч даёт немного больше скорости и уклонения, булава — больше угрозы и другой тип урона |
| Рапира / копьё / посох | критический удар, скорость либо магическая атака и сила воздействия обмениваются на величину ближней атаки |
| Короткий меч / дубина | точные дополнения к двуручному мечу и кувалде; тип, скорость и угроза различаются |
| Кинжал / кортик / сфера | критический удар, уклонение со скоростью либо магический тип и `l`; собственная атака остаётся растущей и не меньше 120 |
| Баклер / щит / башенный щит / том | уклонение и скорость, сбалансированная живучесть, тяжёлая защита с угрозой либо критический удар и `l` |
| Прежняя ткань / церемониальная ткань | одинаковые `H/D`; скорость и уклонение меняются на критический удар, критический множитель и `l` |
| Прежние чары / призрачные доспехи | одинаковые `H/D`; критический удар и высокий `l` меняются на уклонение и скорость |
| Прежняя кожа / новые кожаные вещи | одинаковые `H/D`; уклонение меняется на критический множитель и `l`, а скорость перераспределяется между ячейками |
| Тяжёлые латы / облегчённые металлические вещи | здоровье, защита и угроза меняются на скорость, уклонение, критический удар и `l` |
| Ткань / кожа / латы / чары | тип защиты остаётся самостоятельным противодействием; числовое сходство двух строк разных типов не делает их взаимозаменяемыми |
| Лук / длинный лук | более высокая скорость на дистанции 3 либо больший устойчивый урон на дистанциях 3–4 |
| Арбалет / ритуальный посох | одинаковый ритм Разрушителя с разным типом атаки |
| Алебарда / посох со сферой | одинаковая постоянная основа Тактика с разным типом атаки и разной формой рук |

Двуручный меч и кувалда являются точными постоянными эквивалентами соответственно `sword+shortsword` и `mace+club`; это не делает остальные пары хуже по определению. Алебарда и кувалда заранее помечены для обязательного сравнения со всеми 45 парами без модификаторов: их дальность, тип, угроза и сила воздействия не разрешено считать достаточной компенсацией без боёв. Баклер отдельно проверяется на всех пяти уровнях, поскольку значительная часть его выбора заключена в неизменных уклонении и скорости.

Каждая из двадцати пар доспехов имеет хотя бы одно строгое преимущество с обеих сторон. Это только проверка отсутствия покомпонентного превосходства: она не назначает обменный курс вторичных характеристик. Матрица шага 12 отдельно сравнивает каждую замену, четыре полных новых семейства и смешанные крайние комплекты.

Таким образом, «улучшением» является только развитие самого экземпляра по редкости и усилению. Смена `ItemObject.code` должна означать альтернативу, а не обязательную следующую ступень.

## Корзины общего отбора

| Переданная ячейка и вид объекта | Число вариантов | Равновероятные `ActiveEnum` |
|---|---:|---|
| Атакующая `ОСН` | 8 | `DOUBLE_ATTACK`, `BERSERK`, `BLEEDING`, `KNOCKBACK`, `PRECISE_STRIKE`, `PENETRATION`, `ACCUMULATION`, `TEMPO_BREAK` |
| Атакующая `ВТОР` | 8 | тот же набор |
| Защитная `ВТОР` | 4 | `BERSERK`, `KNOCKBACK`, `GUARD`, `TEMPO_BREAK` |
| `КОРП` | 4 | `COUNTER_ATTACK`, `THORNS`, `SELF_HEAL`, `GUARD` |
| `НОГИ` | 2 | `SELF_HEAL`, `RETREAT` |
| `ОБУВЬ` | 3 | `HIT_AND_RUN`, `RETREAT`, `FEINT` |
| `ГОЛОВА` | 2 | `COUNTER_ATTACK`, `HIT_AND_RUN` |
| `РУКИ` | 2 | `THORNS`, `FEINT` |

Все восемь предметов для двух рук видят один и тот же набор из восьми модификаторов при трёх путях: случайной выдаче через основную руку, выдаче через вторую руку и первом повышении редкости через первую занятую ячейку. Это обязательный инвариант: каждый будущий ручной модификатор типов `ATTACK` или `ANY` должен симметрично перечислять обе руки либо осознанно возвращать этот проект на пересмотр.

По всему каталогу существует 264 допустимые пары «объект — модификатор»: прежние 212 и ещё 52 от двадцати новых доспехов. Добавка раскладывается по ячейкам как `16 + 8 + 12 + 8 + 8` для корпуса, ног, обуви, головы и рук. Пустых корзин нет. Каждый модификатор может находиться ровно на двух совместимых ячейках полного комплекта; предмет для двух рук считается двумя занятыми ячейками. Поэтому при действующих 1–4 очках редкости:

- максимум каждого умения равен `2 × 4 = 8`;
- для каждого умения достижимы все итоговые значения 1–8;
- один предмет для двух рук даёт только 2, 4, 6 или 8 очков;
- ни одна штатная сборка больше не создаёт бесполезные 12–16 очков поверх предела формулы.

Узкие корзины для ног, головы и рук сознательны. Число предметов в ячейке не меняет корзину одного экземпляра: новый предмет получает те же два или три равновероятных варианта, что прежний предмет той же ячейки. Добавление ещё одного модификатора в такую корзину изменило бы вероятность каждого прежнего результата и потому считалось бы отдельным изменением каталога.

## Исторические назначения

Из 196 пар, которые прежний общий отбор мог создать на существующих 40 объектах, 136 остаются допустимыми для новых выдач, а 60 становятся только историческими. Двадцать два новых объекта не увеличивают этот исторический набор, потому что их ещё не существовало в выдаче:

| `ActiveEnum` | Прежние ячейки, исключённые из нового отбора | Число старых пар «объект — модификатор» |
|---|---|---:|
| `COUNTER_ATTACK` | `НОГИ`, `РУКИ` | 8 |
| `THORNS` | `НОГИ` | 4 |
| `BERSERK` | `КОРП` | 4 |
| `HIT_AND_RUN` | `РУКИ` | 4 |
| `KNOCKBACK` | `ОБУВЬ`, `РУКИ` | 8 |
| `SELF_HEAL` | `ОБУВЬ`, `ГОЛОВА` | 8 |
| `RETREAT` | `ГОЛОВА` | 4 |
| `FEINT` | обе руки | 20 |
| **Итого** |  | **60** |

Это множество возможных исторических сочетаний, а не утверждение, что каждое уже существует в рабочей БД. На шаге 11 нужна фактическая выгрузка с группировкой хотя бы по `ItemObject.code`, `Modifier.code`, редкости, уровню усиления и признаку экипировки.

Правила совместимости применяются только к новому назначению. Исторический экземпляр должен по-прежнему читаться, показываться, экипироваться, давать прежний `modifier_id`, участвовать в сумме очков и расти по редкости. Рост необычного или более редкого предмета не выбирает модификатор заново; только переход обычного предмета к необычному делает выбор по новой корзине. Старые `Modifier.code` и их идентификаторы нельзя удалять, менять им `ActiveEnum` или незаметно переназначать уже выданный предмет.

## Безопасное включение

1. Шаги 8–10 реализуют модель и описывают 40 изменённых и 22 новых объекта в отдельной неактивной версии данных. Проверочный загрузчик работает только с этой версией; действующие строки БД и набор добычи он не заменяет.
2. Шаг 11 вводит явную версию каталога или признак участия в добыче, после чего обновляет существующие строки по сохранённым `code` и вставляет в БД 22 новых строки как неактивные. Они не попадают в случайную выдачу, пока действует прежняя версия каталога.
3. Шаг 12 пересчитывает все строки и выполняет матрицу боёв. Только принятый результат разрешает одной операцией включить подготовленную версию для новых выпадений и новых боевых снимков игроков.
4. Уже созданные снимки боя и прежние умения неигровых персонажей остаются на своих сохранённых версиях.

Удаление строки из `TOML` не является способом вывода предмета или модификатора из обращения: загрузчик не удаляет связанную строку БД, а исторические экземпляры имеют внешние ключи. В этой версии вывода из добычи нет, но явный признак всё равно нужен для будущих изменений.

В действующем пути случайного выпадения сначала равномерно выбирается ячейка, а затем объект из активного набора внутри неё. После расширения условная вероятность конкретного доспеха в выбранной неоружейной ячейке уменьшается с `1/4` до `1/8`, но вероятность типа защиты остаётся `2/8 = 1/4`. Это намеренное следствие добавления альтернатив, которое шаг 11 проверяет отдельно; скрытые веса отдельных кодов здесь не вводятся. Прямой выбор предмета в магазине и выдача конкретного `code` этим расчётом не описываются.

## Проверенные инварианты проекта

- 62 уникальных добываемых кода: 18 атакующих и 44 защитных объекта; для каждого типа защиты существует 11 объектов.
- 5 объектов только основной руки, 9 только второй руки и 8 предметов для двух рук; среди девяти вторых рук пять атакующих и четыре защитных.
- В каждой из пяти неоружейных ячеек находится по 8 объектов — по 2 каждого типа защиты.
- 53 допустимых блока рук и `8⁵ = 32 768` сочетаний доспехов дают `53 × 32 768 = 1 736 704` физических полных комплекта.
- Каждая положительная основа принадлежит множеству `60, 120, 180, 240, 300, 360, 420, 480, 540, 600, 720`.
- Все части атаки имеют `1 ≤ dmin ≤ dmax ≤ 4`; каждая положительная атака и защита не меньше 60; здоровье равно нулю либо не меньше 60.
- Все 15 максимумов очков равны 8; все 105 пар разных модификаторов достижимы; число допустимых пар «объект — модификатор» равно 264.
- В полной экипировке наблюдаются `L=80`, `L=90` и `L=100`; максимальная сумма `lᵢ` равна 20, поэтому штатного отсечения нет.
