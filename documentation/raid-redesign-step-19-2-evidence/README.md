# Материалы шага 19.2

[Проект](../raid-redesign-step-19-1-anomaly-design.md), [условия основной выборки](protocol.md). Это сравнение двух строев аномалии при прежних `legacyPower()` и `0,92`, а не калибровка сложности или проверка выплат.

## Исходная версия

`baseline-sources.tar.gz` содержит прежние генератор/тесты и проект 19.1; суммы — в `baseline-metadata.json`. `baseline-classes-v2.tar.gz` содержит прежний класс генератора и служебный класс `$1`, одним свежим `javac --release 24` собранные до правки. Загрузчик подменяет только это семейство, общие бой/модели/случайность остаются едиными. Отсутствие прежнего класса — ошибка, не повод использовать нынешний.

Для повторения распаковать архив в новый временный каталог; не перезаписывать рабочие исходники. Например из корня проекта:

```sh
seeker_anomaly192_baseline=$(mktemp -d /tmp/seeker-anomaly-192.XXXXXX)
tar -xzf documentation/raid-redesign-step-19-2-evidence/baseline-classes-v2.tar.gz \
  -C "$seeker_anomaly192_baseline"
```

## Команды

Сборка выполняется из `game`: `mvn -o -B -ntp clean package`. В использованной среде JDK 25.0.1, цель компиляции 24 и явный агент Mockito. Приложение и бот не запускаются; PostgreSQL не требуется. `seeker_anomaly192_classpath` должен содержать `game/target/test-classes`, `game/target/classes` и зависимости тестов; дальнейшие команды запускаются из корня проекта.

```sh
java -Xmx2g -cp "$seeker_anomaly192_classpath" \
  ru.homyakin.seeker.game.battle.Step192AnomalyFormationStudy \
  plan NEW_RUN_DIRECTORY "$seeker_anomaly192_baseline"
```

С теми же классами выполнить `run NEW_RUN_DIRECTORY BASELINE_CLASSES`, затем новым процессом `replay NEW_RUN_DIRECTORY NEW_REPLAY_DIRECTORY BASELINE_CLASSES`. Во всех командах `BASELINE_CLASSES` — тот же каталог исходного класса. Выходные каталоги должны быть новыми; условия/суммы сравниваются до исполнения.

```sh
node documentation/raid-redesign-step-19-2-evidence/validate-study.mjs \
  RUN_DIRECTORY REPLAY_DIRECTORY NEW_REPORT_JSON
```

Отдельная историческая сверка, без новых боёв:

```sh
java -Xmx2g -cp "$seeker_anomaly192_classpath" \
  ru.homyakin.seeker.game.battle.Step192AnomalyFormationStudy \
  compatibility NEW_COMPATIBILITY_JSON "$seeker_anomaly192_baseline"
```

## Состав результатов

Основная выборка [`run-v2/`](run-v2/summary.json): 136 логических условий, 272 сочетания версии/условия, 7840 боёв. Сохранённые 1960 индексов пар общие для версий; зеркала зависимы. При N2 до исходов выбраны десять пар каждой реальной ветви численности. Шаблоны/размеры/профили и дополнительные направления раскрываются отдельно. Два имени сервисного режима не удваивают число независимых боёв одной фабрики.

`replay-v2/` — 96 заранее выбранных полных строк, повторённых отдельным процессом. [`validation.json`](validation.json) — успешный независимый пересчёт; `historical-compatibility-v2.json` — 192 точных сравнения прежних версий, включая нормализацию N0/6/128. `source-lock.sha256` зафиксировал 261 файл до основной выборки, включая 256 публичных входов, протокол, архивы и нынешние скомпилированные классы. `inputs.sha256` и `artifacts.sha256` относятся к окончательным входам и материалам после завершения.

Журналы: `targeted-tests.log` — 116 точечных проверок генератора/сервиса; `clean-package.log` — окончательная чистая сборка всего модуля, 2057 проверок, 29 прежних/условных пропусков, без ошибок. Две предыдущие успешные сборки до последних дополнений стенда сохранены в `clean-package-before-preflight.log` и `clean-package-before-loader-fix.log`. Окончательное планирование — `plan-v2.log`, бои — `run-v2.log`, историческая сверка — `historical-compatibility-v2.log`, повторы — `replay-v2.log`, независимый пересчёт — `validation.log`. Исходные журналы не переформатируются ради пробелов.

Все бои завершились, максимум 70 тактов; все 96 повторов совпали целиком. Основное семейство: 1701/2400 → 1730/2400 побед. Это не приёмка сложности: одиночки значительно слабее групп N3–5, а бесплатные комплекты дали 101/240 → 48/240. Полные разрезы — в [`отчёте`](../raid-redesign-step-19-2-anomaly-formation.md) и независимом пересчёте. Не вводится порог 50/50 и не смешиваются основные/вспомогательные семейства ради красивой средней.

Заключительные независимые разборы: [технический](independent-review-technical.md) и [балансовый](independent-review-balance.md). Прежние 14 наборов материалов / 740 файлов неизменны: `previous-artifacts-validation.json`. Сравниваются сами сохранённые материалы, а не старые суммы нынешних исходников после разрешённой правки.

Предметы, награды, рейтинг, состояние событий, PostgreSQL и выпуск этой работой не меняются. Пустой состав V3 явно отклоняется до журнала/выплат; дальнейшее завершение такого события не считается решённым и остаётся в 19.4. Изменения технической оценки/сложности относятся к отдельному решению 19.3.

До основной выборки первое планирование остановилось из-за неполной изоляции служебного класса Java. `plan.log`, `historical-compatibility.log`, одноклассовый `baseline-classes.tar.gz`, `baseline-metadata-before-loader-fix.json` и `validate-study-before-loader-fix.mjs` сохраняют эту попытку. Ни один бой тогда не выполнялся. Исправленный загрузчик получает отдельную проверку; последующие журналы и каталоги используют новые имена.
