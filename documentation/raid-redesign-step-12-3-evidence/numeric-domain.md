# Числовая область экипировки кандидата 12.3

Кандидат: `SCALING_V4`, развитие `V1`, умения игроков `SCALING_SKILLS_V2`. Проверка относится к семи непересекающимся ячейкам снаряжения и уровням `+0…+75`, а не к любому допустимому числу `int` в произвольном неигровом персонаже.

## Что проверяется

`EquipmentReleaseNumericDomainTest` охватывает все 63 получаемых и семь начальных объектов на каждом из 76 уровней: чтение состояния и видимых характеристик, независимый прямой расчёт основы, неубывание здоровья, каждой части атаки и защиты, неизменность вторичных характеристик и ключей частей атаки. Для каждого объекта фактический `StormEnhanceTechnicalLimit` должен разрешать состояние `+75`; цена перехода с `+74` представима, попытка с `+75` отклоняется. Это временная техническая граница текущих цен, а не ограничение баланса. Изменение цен требует нового расчёта области.

Отдельно для каждого уровня суммируются независимые максимумы каждой характеристики по семи ячейкам. Двуручный предмет разрешено учитывать дважды — как заведомое завышение. Максимумы разных полей не обязаны быть совместно достижимы. Любой настоящий непересекающийся комплект ограничен этой оболочкой; перебор всех физических сочетаний для такого вывода не нужен.

| Показатель | Завышенная граница на `+75` |
| --- | ---: |
| Здоровье | 6075 |
| Сумма всех частей атаки, включая несовпадающие расстояния | 2160 |
| Сумма защиты всех типов | 1485 |
| Скорость | 204 |
| Шанс критического удара | 19% |
| Уклонение | 18% |
| Множитель критического удара с общей основой 1,2 | 1,75 |
| Сумма вкладов силы воздействия | 27 |
| Сила воздействия после общего ограничения | не более 100 |
| Базовая угроза | 66 |

Границы рассчитаны независимым чтением чисел `TOML`; новый тест закрепляет их и печатает оболочку в журнал. Все **154 проверки** выполнены успешно в окончательной полной сборке — [журнал](full-build-final.log). Одно наличие исходника теста не засчитывалось как успешное выполнение.

Для справочной мощи даже несовместимая комбинация всех верхних границ даёт менее 58 276. В расчёте завышения приняты максимальный вес защиты 1,25, уклонение 18%, скорость 204 и множитель 1,75. Это значительно ниже границы показываемого `int`; числа здоровья, атаки и защиты также не переполняют промежуточные суммирования формулы. Проверка дополнительно ограничивает вероятности и коэффициенты для всех достижимых сумм очков `0…28`; восьми эффективных очков хватает для максимального действия умения.

Для экипировки без внешних эффектов основа здоровья «Шипов» не превышает `3 × 6075 = 18 225`, максимальное запрошенное «Самолечение» — 456. Добавлен завышенный учёт прибавки «Берсерка» и округления каждого типа атаки: обычный критический удар и отдельные пакеты масштабируемого урона остаются внутри `int` и после разброса.

## Исправленные края и ограничения вывода

`Step12CombatNumericSafetyTest` отдельно проверяет прежние ошибки: сложение здоровья при лечении возле границы `int`, полный обработчик «Самолечения» при двух миллиардах здоровья, а также обе ветви `min(3H;40A)` «Шипов», в том числе когда выбранная основа превышает `int`, но итоговый урон представим. Обычные пакеты событий сохранены; для большой основы множитель выбранной ветви переносится в коэффициент без потери точного произведения.

Проверки не объявляются универсальным доказательством безопасности любого временного эффекта, произвольного неигрового персонажа, параметров после будущей смены цен или записи предмета выше `+75` в рабочей БД. `ItemProgression` проверяет представимость отдельных состояний, а не ограничивает все входы боя. Перед настоящим развёртыванием сохраняются обязательные сверка фактических уровней, резервная копия и согласованный порядок включения. Увеличение технической области на шаге 18 требует повторной проверки полных боевых входов.
