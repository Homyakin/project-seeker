Всего **681 000** боёв: 237 000 пробных и 444 000 подтверждающих. Последние 222 условия не являются новым всеобщим порогом допуска. Во всех семи прогонах нет ничьих и незавершённых боёв; максимальная длительность — 214 раундов. Пересечений начальных значений между прогонами нет. Варианты одной причинной проверки намеренно используют одинаковые значения внутри прогона.

У каждого префикса сохранены:

- `-run.properties`: корень, объём и условия запуска;
- `-cases.json.gz`: определения, полная фактическая экипировка и известные затраты;
- `-battles.tsv.gz`: каждый исход, начальное значение, порядок сторон, длительность и показатели обеих команд;
- `-summary.tsv`: исходы, точечные интервалы и средние показатели;
- `-complete.properties`: завершение без изменения проверяемых входов;
- `.log`: журнал исполнения.

Основной исполнитель также сохраняет `-inputs.sha256`; отдельная экономическая проба сохраняет хэш своего исходника и проверенного полного перечня входов до и после запуска. Она использует тот же проверенный боевой исполнитель, а не собственную реализацию правил.

`summarize-study.mjs` строит связанные разности из исходов, проверяя совпадение начальных значений. Результаты — `*-comparisons.tsv`. Границы Хёффдинга точечные 95%: около ±4,29 пункта для отдельного исхода и ±8,59 для парной разности на 1 000 парах. Они не дают одновременной гарантии всей матрицы. При незавершённом исходе скрипт отказывает, а не выдаёт отобранную долю побед за общий результат.

Первый подтверждающий фильтр содержал `SLASH_CLOTH` вместо `SLASH_PLATE`: поэтому в нём 189, а не 201 условие. Пропущенные 12 выполнены отдельным дополнением с новыми начальными значениями. Прежние файлы и фильтр не переписывались. После подтверждения игровых чисел не меняли; последующие опыты добавляли противников, а не подгоняли предметы или умения.

`reference-teams.json` содержит 18 точных образцов: три ступени × основные размеры 3/7/15 и три специализированных состава. ## Точные проверки и PostgreSQL

`full-build-final.log` — окончательный успешный `mvn clean package`: **1 256 учтённых тестов, 1 237 выполнены, 19 намеренно отключены**, ошибок и нарушений Checkstyle нет. Все семь `EquipmentCatalogPostgresIntegrationTest` выполнены, без пропусков. `full-build-postgres.log` — предшествующая успешная полная сборка до добавления заключительных ответных условий.

Фактическая среда: Axiom JDK 25.0.1, Maven 3.9.12, целевая версия Java в POM — 24; выполнение на JDK 24 этим журналом не заявляется. Для Mockito использован явный агент. База — отдельная PostgreSQL **16.15**, официальный образ `postgres:16`, полученный с хэшем `sha256:9e2cf6287f25c3151f4c9421ccce2b17f3e60061c111a29165e0d2cdd9ff0a97`.

Временная БД `seeker_step12_3` слушала только `127.0.0.1:55434`, данные находились во временной памяти. Тесты создавали и удаляли собственные схемы. Проверочные контейнеры `seeker-step12-3-pg16` и первоначальный неиспользованный `seeker-step12-3-db` удалены после выполнения; пользовательские БД и образы не удалялись. Данные опыта восстанавливаются повторным запуском тестов в новой пустой БД.

Сохранены и неуспешные подготовительные журналы: `postgres-preflight.log` — шесть успешных вариантов и слишком длинное имя тестового персонажа в седьмом; `postgres-sequence.log` — повтор со старым скомпилированным классом после неполной пересборки. После сокращения тестового имени и `clean` последовательный сценарий прошёл (`postgres-sequence-clean.log`), затем все семь дважды прошли в полной сборке. Это не скрытые успешные квитанции. Прочие `compile-*`, `technical-*`, `niche-compile.log` и `final-study-compile.log` сохраняют промежуточные проверки.

[Числовая область](numeric-domain.md) отдельно описывает покрытие всех 70 объектов на `+0…+75`, завышенные границы полного комплекта и ограничения вывода для внешних эффектов и произвольных противников.

## Команды воспроизведения

Из `game/`, с доступной отдельной PostgreSQL и новым каталогом результатов:

```bash
env JAVA_HOME=/home/user/.jdks/axiomjdk-25.0.1 \
  JAVA_TOOL_OPTIONS=-javaagent:/home/user/.m2/repository/org/mockito/mockito-core/5.18.0/mockito-core-5.18.0.jar \
  SEEKER_POSTGRES_TEST_URL=jdbc:postgresql://127.0.0.1:55434/seeker_step12_3 \
  SEEKER_POSTGRES_TEST_USER=dev SEEKER_POSTGRES_TEST_PASSWORD=dev \
  /opt/apache-maven-3.9.12/bin/mvn clean package

study_cp=$(sed -n 's/.*<property name="java.class.path" value="\([^"]*\)"\/.*/\1/p' \
  target/surefire-reports/TEST-ru.homyakin.seeker.game.battle.Step123BattleStudyTest.xml)

/home/user/.jdks/axiomjdk-25.0.1/bin/java -Xmx2g \
  -Dstep123.seed=2026102305 -Dstep123.pairs=1000 \
  '-Dstep123.filter=^CLOTH_|^SINGLE_(robe|cloth_chausses)_(BLUNT_LEATHER|SLASH_CLOTH)_|^MOBILE_NICHE_|^CONTROL_' \
  -Dstep123.output=/absolute/new/output/confirmation \
  -cp "$study_cp" ru.homyakin.seeker.game.battle.Step123BattleStudy

pressure_classes=$(mktemp -d /tmp/seeker-step123-pressure.XXXXXX)
/home/user/.jdks/axiomjdk-25.0.1/bin/javac --release 24 -cp "$study_cp" \
  -d "$pressure_classes" ../documentation/raid-redesign-step-12-3-evidence/AccessiblePressureStudy.java
/home/user/.jdks/axiomjdk-25.0.1/bin/java -Xmx1g -cp "$pressure_classes:$study_cp" \
  ru.homyakin.seeker.game.battle.AccessiblePressureStudy /absolute/new/output/accessible-pressure
```

Каталог вывода должен существовать, префикс — быть новым. Остальные корни, фильтры и объёмы приведены в соответствующих `-run.properties`; исходный ошибочный фильтр выше оставлен именно для воспроизведения 189 условий, а не исправлен задним числом. Сохранять результаты поверх этих файлов нельзя. Старые одноразовые итоговые исполнители шага 12 ради воспроизведения 12.3 не запускаются.
