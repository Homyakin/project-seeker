## Метод

Новая техническая оценка `Q` — произведение суммы индивидуальных нейтральных запасов здоровья с защитой и суммы индивидуальных ожидаемых обычных ударов за время с максимальным профилем дальности. Она симметрична для игроков и противников; не вызывает службу справочной мощи, не назначает цену умениям и не оценивает конкретное противодействие текущему врагу.

Поправка `C=0,5900075417594784` выбрана **один раз по характеристикам**, не по доле побед: у средней исходной тройки на уровне 25 сохраняется `Q` настоящих исходных противников. Варианты используют ту же поправку; иной состав или число бойцов могут менять её фактическую сложность. Окончательное игровое значение не принято.

Старый контроль получает множитель настоящего `RaidGenerator`, после чего использует точное повторение его фабрики с отдельно зафиксированной случайностью окончательного состава. Это изолирует характеристики от числа проб поиска, но не повторяет прежнюю случайность начальных показателей противников из архивного шага 15. Отдельная проверка фабрики сравнивает реальные характеристики, дальность, позиции, очки и версию умений; случайные идентификаторы и начальное накопление инициативы не сравниваются.

Составы `N3→4` — одна и та же тройка плюс обычный Громила. Старые предметы, позиции и тактики сохраняются. У каждого порядка сторон свежие боевые объекты; начальные значения генерации и боя общие для сравниваемых вариантов и размеров. Два порядка — одна независимая пара. Общие начальные значения между разными опытами означают, что их объёмы **нельзя складывать как независимые наблюдения одной вероятности**.

## Проверка данных

`validate.cjs` независимо читает весь сжатый поток: проверяет уникальность и полноту пар, состав условий, начальные значения, числовые ограничения, разложение и целевую оценку, суммы исходов, длительность и сводные интервалы. Это проверка внутренней согласованности, не доказательство того, что формула правильно предсказывает бой.

```sh
node documentation/raid-redesign-step-15-1-evidence/validate.cjs RUN_DIRECTORY
```

Проверены все шесть потоков; отчёты сохранены в `validation/`. Числовая согласованность первоначального случайного опыта не делает его статистически пригодным: его ошибка выборки ветвей отдельно исключена из выводов.

Для разности связанных пар используется диапазон `[-1;1]` и точечная 95-процентная граница Хёффдинга `sqrt(2 × ln(40) / число_пар)`. При 100 парах это ±27,16 процентного пункта; при 20 — ±60,74. Это не одновременная гарантия всей матрицы. Маленькая выборка подходит для отбраковки очевидно плохого направления, а не для объявления отсутствия крупного вреда.

## Повторение и границы

Первая матрица из 7200 боёв независимо повторена основным агентом в новом процессе Java: сжатый поток и сводка совпали побайтно. Повтор не увеличивает независимую выборку. Контрольная сумма потока: `947b8548f8748a9f1a3d9eed20dd43bbb12a7be0f4b8a6c0f3a34fd3b4d1bd8a`; сводки: `1eb94ba2c05013d8ee7a69d3595d734447f8b3a74d5aa4d023ff59ddb9bacea4`.

Окончательный вариант из 4880 боёв также независимо скомпилирован во временную папку и повторён основным агентом в другом процессе. Сжатый поток совпал побайтно: `875bb4283015c554ece468155d5219aea2adcafaaa5e827ebbe07108388fb1f2`. Сводки точно равны после разбора JSON; различаются только порядок двух полей описания и завершающий перевод строки. Эти поясняющие поля были уточнены после первого запуска, сырой поток не менялся. Подробности — `replay-receipt.json`.

Среда: JDK 25.0.1, цель компиляции 24; использованы уже собранные классы шага 15, без изменения `game/target`. В этом проектном исследовании Maven и полная сборка не запускались. Для восстановления исходной основы используется снимок `sources.tar.gz` из архива шага 15 поверх указанного там исходного коммита. Полный снимок окружения, секреты и игнорируемые настройки в материалы не включаются.

Прототипы компилируются отдельно с классами и зависимостями тестового стенда:

```sh
javac --release 24 -cp 'GAME_TEST_CLASSES:GAME_CLASSES:DEPENDENCIES' -d TEMP_CLASSES SOURCE.java
java -Xmx768m -cp 'TEMP_CLASSES:GAME_TEST_CLASSES:GAME_CLASSES:DEPENDENCIES' \
  ru.homyakin.seeker.game.battle.ScalingQPrototype NEW_OUTPUT_DIRECTORY
```

Для окончательного варианта отдельно скомпилировать `bounded-tail-results/ScalingQStructureProbe.java` вместе с `ScalingQPrototype.java`, затем из `game`:

```sh
java -Xmx768m -Dprobe.boundedTail=true \
  -cp 'TEMP_CLASSES:GAME_TEST_CLASSES:GAME_CLASSES:DEPENDENCIES' \
  ru.homyakin.seeker.game.battle.ScalingQStructureProbe NEW_OUTPUT_DIRECTORY
```

Запуск — из `game`, чтобы пути каталога оставались настоящими. Для каждого опыта нужна новая папка вывода. Точные отдельные исходники и параметры последующих опытов сохраняются с их результатами; более поздний вариант не заменяет исходник раннего опыта.

Все проверенные варианты — технические приближения. Не доказаны отсутствие злоупотребления вне выбранных случаев, универсальная монотонность побед, пригодность для других видов походов/аномалий и окончательная экономика наград. Промежуточный безопасный предел множителя прототипа не заменяет требуемого вывода рабочего предела со всеми весами; фактические числа опытов проверяются отдельно и находятся далеко от переполнения. Полные журналы действий всех боёв не сохранялись.

## Состав пакета

`prototype-evidence.tar.gz` содержит все исходники прототипов, полные входы, сжатые потоки, сводки, примеры начального состояния и пояснения каждого опыта. Контрольная сумма архива: `69f1b62349fab14b5a8b19b42b5f3bd381dde7141f9db0bfce799025fe24d4e5`. Архив распакован в отдельную папку; все его внутренние суммы `all-evidence.sha256` проверены. Все 198 исходных файлов основы также совпадают с `inputs.sha256` архива шага 15.

| Папка внутри архива | Условий / боёв | Назначение |
|---|---:|---|
| `results/` | 60 / 7200 | Нынешний контроль, командная оценка, оценка с распределением рядов |
| `structure-results/` | 46 / 5200 | 6 условий/1200 боёв пригодного диагностического контроля; 40 условий/4000 боёв ошибочного случайного опыта исключены из среднего по ветвям |
| `random-mixed-results/` | 40 / 4000 | Исправленный случайный опыт; также не выбран |
| `thin-guard-results/` | 16 / 1600 | Отвергнутый менее прочный Страж |
| `size-attenuation-results/` | 52 / 3360 | Отвергнутая неограниченная поправка численности |
| `bounded-tail-results/` | 90 / 4880 | Выбранный проектный кандидат с ограниченным ослаблением |

Итого выполнено 26240 исследовательских боёв, в том числе 4000 с непригодной выборкой случайной ветви; эти числа не являются одной независимой выборкой и включают повторяющиеся контрольные условия. Два отдельных повтора 7200 и 4880 боёв не добавлены к этому итогу. Все шесть потоков завершены, ничьих и незавершения нет.

Внутри также находятся `controls.md` с последовательностью отклонённых гипотез и ограничениями, `FactoryEqualityValidation.java`/`factory-validation.log` с проверкой 96 противников, контрольные суммы использованных боевых классов. Точные отдельные исходники каждой фазы сохраняются рядом с её потоком. Для ошибочного опыта есть `INVALID_RANDOM_BRANCH_SAMPLING.md`; его записи не переименованы задним числом.

Пример безопасного извлечения и проверки из корня репозитория:

```sh
scaling_evidence_dir=$(mktemp -d /tmp/seeker-scaling-review.XXXXXX)
tar -xzf documentation/raid-redesign-step-15-1-evidence/prototype-evidence.tar.gz -C "$scaling_evidence_dir"
(cd "$scaling_evidence_dir" && sha256sum -c all-evidence.sha256)
node documentation/raid-redesign-step-15-1-evidence/validate.cjs "$scaling_evidence_dir/bounded-tail-results"
```

`artifacts.sha256` проверяет внешние файлы этого пакета, кроме самого списка. Прежний архив шага 15 не изменялся.
