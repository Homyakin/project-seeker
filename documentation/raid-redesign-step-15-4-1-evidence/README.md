## Содержимое

В обоих каталогах опыта сохранены без изменения:

- `Step1541SeparateScalingProbe.java` — исходник соответствующего замороженного помощника. Одинаковое имя класса не означает одинаковую матрицу двух фаз; каждый компилировался в отдельный каталог вне игрового модуля.
- `frozen-preparation` — входы, параметры и начальные числа до исполнения боёв; `prebattle-freeze.sha256` — исторические контрольные суммы. Вторая фаза дополнительно сохраняет копии исходника до и после исполнения.
- `screen/battles.jsonl.gz` — **полный исходный gzip**, не выборка и не перепаковка. В каждой строке есть предметы, начальные состояния, подготовленные показатели, цели, отдельные множители, индивидуальные итоги и контрольные суммы действий/трассировки. Полные журналы действий не сохранялись.
- `screen/{manifest,inputs,seeds,summary,analysis,validation}.json` — параметры и результаты; у подтверждения есть также отдельная проверка анализа.
- `controls.md`, проверяющие/аналитические программы, выбранные хэши исходников и классов. В `confirmation-study/RESULTS.md` находятся все 24 итога и оба семейства интервалов.

`analytic-design` содержит первоначальный численный проект, 1062 проверки, независимое чтение разведки и заключительный пересчёт всех 12 000 парных оценок и 24 интервалов. Часть исторических помощников ссылается на исходные временные пути; для переносимой проверки готового пакета используйте команды ниже.

`methodology` содержит отдельную рецензию метода и 93 004 числовые проверки. Это проверки помощников, не новые модульные тесты игры.

`screen-independent-validation` и `confirmation-independent-validation` содержат собственные полные проверки исходных потоков. Они заново подготавливают игроков из предметов, пересчитывают обе оси, характеристики врагов, исходы по конечному здоровью, парные сводки и случайные идентификаторы/инициативу. Проверки не используют код производящего валидатора. Исходная проверка разведки сохранена; её переносимая копия меняет только разрешение исторических абсолютных путей контрольных сумм, не математические условия и не исходы. Подробности — `PORTABLE.md`.

## Проверка без новых боёв

Нужны Node.js и `sha256sum`. Из корня репозитория:

```sh
sha256sum -c documentation/raid-redesign-step-15-4-1-evidence/artifacts.sha256
study_checks=$(mktemp -d /tmp/seeker-step15-4-1-checks.XXXXXX)
node documentation/raid-redesign-step-15-4-1-evidence/screen-independent-validation/validate-split-screen-portable.cjs \
  documentation/raid-redesign-step-15-4-1-evidence/screen-study > "$study_checks/screen.json"
node documentation/raid-redesign-step-15-4-1-evidence/confirmation-independent-validation/validate-split-confirm.cjs \
  documentation/raid-redesign-step-15-4-1-evidence/confirmation-study > "$study_checks/confirmation.json"
node documentation/raid-redesign-step-15-4-1-evidence/confirmation-independent-validation/summarize-confirm.cjs \
  "$study_checks/confirmation.json"
```

Эти команды читают сохранённые данные и печатают новые квитанции вне пакета. Они не запускают Java или новые бои, не переписывают архивные исходы и не увеличивают выборку. Пути в новых квитанциях могут отличаться от исторических. Производящие программы `validate.py`/`analyze.py`, наоборот, записывают производные отчёты в каталог опыта; для их повторения сначала сделайте отдельную копию опыта.

Контрольные суммы полных потоков:

| Поток | Исходный gzip SHA-256 | Распакованный JSONL SHA-256 |
|---|---|---|
| Разведка, 6000 строк | `618cf6f483d3503b19b340dd4712a7c652a310f005d6561f93a9b0a1292ca444` | `ac73a325903d80f2b860d255a80c8b86fdb2cac21281253353bf5a33708eabb4` |
| Подтверждение, 24 000 строк | `056050671b53a779f712fc44fbf920f49780d8473bb59bb27d9f433c78102f7f` | `92f894baa5bdc50e55a41026fbc9b67bbbad02010f34d7d2f43321b061fba8a9` |
