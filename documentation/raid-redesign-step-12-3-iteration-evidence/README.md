## Состав свидетельств

[Архив исследований](studies.tar.gz) и [его контрольная сумма](studies.sha256) содержат итоговые показатели, полные определения и компактные исходные записи 14 запусков, включая отдельно обозначенные исключённые данные. В итоговое подтверждение входят **418 000 боёв**, в разведку — **145 440**. Прежние зависимые 42 000 и два технических пробных боя не засчитываются. Перечень всех запусков, корни, размеры и уровни закреплены в [runs.json](runs.json).

Для каждого префикса сохранены `*-summary.json`, `*-cases.json.gz`, `*-pairs.jsonl.gz`, `*-provenance.json`. Последний файл содержит фактические пути загрузки и отпечатки классов, а не только заявленные версии. Снимки `baseline-helper.tar.gz`, `adaptation-helper.tar.gz`, `counterchain-helper.tar.gz`, `final-helper.tar.gz` сохраняют вспомогательный исходник и только его собственные скомпилированные классы на этапах исследования. `selected-sources.tar.gz` — снимок 62 явно выбранных публичных игровых и проверочных файлов. Это не полная копия приложения.

## Повторный пересчёт

Сначала проверить `sha256sum -c studies.sha256` из этой директории и распаковать архив в новую отдельную папку. Например, из директории с этими сценариями:

```sh
node validate-study.cjs /путь/к/распакованному/core-confirmation
node validate-study.cjs /путь/к/распакованному/protected-confirmation
node validate-study.cjs /путь/к/распакованному/size-confirmation
node validate-study.cjs /путь/к/распакованному/progression-confirmation-independent
node validate-study.cjs /путь/к/распакованному/ritual-counter-confirmation-independent
node audit-seed-independence.cjs /путь/к/распакованному
```

Нужен Node.js 24 и текущее дерево репозитория: проверка ячеек снаряжения читает каталог V5 из игровых ресурсов. На другом дереве сначала сверить `inputs.sha256` или использовать сохранённый снимок выбранных исходников. Сценарии читают поле `seed` как точный целочисленный фрагмент и используют `BigInt`, не округлённый JavaScript `Number`.

`WIN` относится к левому логическому составу независимо от перестановки сторон. Если в таблице показаны победы правой стороны, используется доля `LOSS`. Каждая строка `pairs.jsonl.gz` содержит один порядок сторон; единица независимости — целая пара. Варианты одного набора намеренно связаны начальными значениями. Пять зачтённых подтверждающих запусков не пересекаются между собой или с разведкой; два зависимых первоначальных запуска явно исключены.

Старые `pairMean95` в первых двух разведках не служат доказательством уверенности: при всех победах эмпирическая дисперсия равна нулю. Итоговые `pairedHoeffding95` рассчитаны по ограниченным значениям пар, остаются ненулевой ширины при всех победах и относятся к одной ячейке, не ко всей матрице одновременно.

## Повтор моделирования

Требуется полная сборка нужного рабочего дерева и зависимости `game`; один `HEAD` не описывает существующие незакоммиченные изменения. Исследование использовало JDK 25.0.1, целевой уровень POM 24. Перед ним из `game` прошла команда:

```sh
mvn test -Dtest=Step123ReferenceTeamsTest,Step123BattleRunnerTest,ScalingSkillMathTest,ScalingSkillBookTest
```

Результат: **52 успешных теста, ноль пропусков, ошибок и нарушений Checkstyle**. Это не новая полная сборка и не проверка PostgreSQL.

Скомпилировать `source/Nov07ComparativeStudy.java` через `javac` в новую временную директорию с путём зависимостей из `java.class.path` отчёта `Step123ReferenceTeamsTest`. В пути нужны `game/target/test-classes` и `game/target/classes`; первыми ставятся только собственные вспомогательные классы. Основной класс — `ru.homyakin.seeker.game.battle.Nov07ComparativeStudy`. Первый аргумент — новый незанятый префикс вывода; перезапись запрещена.

Настройки итоговых запусков:

| Префикс | Корень | Пары | Размеры | Усиление | Страж |
|---|---:|---:|---|---|---|
| `core-confirmation` | 2026110704 | 500 | 7 | 0,6 | нет |
| `protected-confirmation` | 2026110706 | 500 | 7,15 | 0,6 | одинаковый легендарный щит с GUARD4 |
| `size-confirmation` | 2026110707 | 500 | 1,3,15,30 | 0,6 | нет |

| `ritual-counter-confirmation-independent` | 2026110710000 | 500 | 7,15 | 0,6 | одинаковый легендарный щит с GUARD4 |

Аргументы JVM: `-Daudit.pairs`, `-Daudit.seed`, `-Daudit.sizes`, `-Daudit.levels`, `-Daudit.guard=LEGENDARY` при наличии Стража; каталог по умолчанию V5. `-Daudit.filter` — регулярное выражение кодов условий, `-Daudit.profiles` — полное совпадение имён составов, `-Daudit.focus` выбирает противостояния с указанным составом. Для точного повтора взять перечень кодов из соответствующей выгрузки и передать их объединением в `audit.filter`; это исключает случайное расширение до всех 50 вариантов. Разведки до расширения используют свой сохранённый снимок вспомогательного исходника.

Исполнитель каждый раз утверждает темп ×1,75 у контекста и всех участников. В каталоге и формулах нет временных подмен. На другой машине пути загрузки могут отличаться: сверяются происхождение и содержимое, а не буквальный путь `/tmp`.
