# Проверочные материалы части 15.3

Дата: 2026-11-08. [Результат и следующее решение](../raid-redesign-step-15-3-balance-validation.md). **Баланс не принят:** воспроизведён крупный штраф за слабого союзника. Это не включение выпуска.

## Состав пакета

- `manifest.json` — девять запусков, параметры, число исполнений, контрольные суммы исходных контейнеров `gzip`, архивных `xz` и распакованного содержимого. Всего 91 200 боёв. Два порядка — одна пара, разные условия не складываются в одну вероятность победы.
- `*-battles.jsonl.xz` — **все исходные строки**, без исключения неудобных исходов и без сокращения полей. `gzip` перепакован в `xz` только для уменьшения объёма; при упаковке побайтно сверены распакованные потоки. Сохраняются полные входы и начальные состояния, командные итоги и контрольные суммы журналов. Полных журналов действий и индивидуальных конечных показателей исходный стенд не записывал.
- `*-summary.json` — оригинальные сводки запусков с парными оценками. Исходные контрольные суммы контейнеров в них намеренно сохранены; это не суммы нового `xz`.
- `causal-aggregate.json` — объединение двух непересекающихся подтверждений по 500 пар. Главные границы учитывают два просмотра; одноразовые производные сохранены отдельно. Входы и диагностические параметры двух серий сверены. Границы точечные, не одновременные для всех условий.
- `*-validation.json`, `matrix-analysis.json`, `ritual-confirmation-analysis.json` — полная проверка соответствующих исходных потоков отдельными программами. Название `confirmedMajorHarm` в машинной причинной проверке — арифметическое пересечение −20 п.п., **не автоматическое применение правила обычного игрока к слабому**; политика отдельно указана в объединённой сводке и отчёте.
- `fillers-mechanics-summary.json`, [независимый разбор](fillers-independent-review.md) — арифметика трёх подтверждённых одиночных условий, свойства противников и командные итоги. Общая 95% граница Бонферрони—Хёффдинга относится только к трём заранее выделенным новым сравнениям `N1→2`.
- [Итоговая независимая рецензия](independent-final-review.md) — рассмотрение обычного добавления, ритуального ответа и штрафа новичкам после завершения боёв и разбора причин. Новая формула в ней не утверждается.
- `ritual-confirmation-inputs.json`, `fillers-*-inputs.json` и `fillers-*-manifest.json` — точные предметы, ячейки, редкости, модификаторы, очки и правила получения входов. Номинальная стоимость вещей не является полной стоимостью получения сборки.
- `Step153FillersProbe.java`, программы `*.cjs`, файлы `*-commands.*` — вспомогательные исходники и точные команды. Временные пути показывают использованную среду; перед повторением заменяются новыми. `excluded-initial-launch.log` — исключённая первая попытка запуска с пустым `JAVA_HOME`; Java не стартовала, боёв было ноль.
- `test-summary.json` — повторная окончательная чистая сборка: 1733 проверки, 1704 успешных, 29 прежних/условных пропусков, ошибок нет, Checkstyle — 0. Команда и безопасный сборщик сводки находятся в [пакете 15.2](../raid-redesign-step-15-2-evidence/README.md). Полные отчёты Surefire, свойства JVM, конфигурация приложения и сборочный журнал сюда не копировались.
- `package-validation.json`, `raw-integrity.json`, `restored-main-*.json` — собственная проверка основного агента: суммы исходов, границы трёх новых подтверждений и двух просмотров, неизменность 203 исходных файлов, точное повторное объединение, все девять потоков и успешное восстановление/повторная проверка 3000 строк Громилы. Восстановленный `gzip` имеет другую контрольную сумму контейнера, но тот же исходный поток.

## Исходная основа

Производственные исходники и параметры этой частью не менялись. Все 203 открытых выбранных файла проверены по `inputs.sha256` из пакета 15.2; снимок `sources.tar.gz` там же имеет SHA-256 `88cb5b11036788a0f211f417d2f2cde81c2268aed373afa31c447686c38cf842` и накладывается на основу `bd142e61a0aa2fc0e1b2117164ab4bc6fac29469` **в новой временной копии**, не поверх чужой работы. `source-basis.sha256` и `class-basis.sha256` фиксируют выбранную основу перед причинными запусками. Отдельный помощник компилировался вне `game/target`.

Среда: JDK 25.0.1 с целью компиляции 24, Maven 3.9.12, явный агент `Mockito` 5.18.0, `Node.js` и `xz`. Бои запускались до повторной `clean package`; во время пересоздания `target` новые бои не выполнялись. БД, приложение и бот не запускались; обычная конфигурация не переключалась. Посторонний `InMemoryLockServiceTest` не редактировался и исключён из снимков, но виден полной сборке.

## Проверка целостности

Из корня репозитория:

```sh
sha256sum -c documentation/raid-redesign-step-15-3-evidence/artifacts.sha256
node documentation/raid-redesign-step-15-3-evidence/verify-raw.cjs
node documentation/raid-redesign-step-15-3-evidence/verify-summary.cjs
sha256sum -c documentation/raid-redesign-step-15-2-evidence/inputs.sha256
```

`verify-raw.cjs` проверяет все девять архивов и хеши распакованных потоков. Это проверка целостности, не повторная приёмка баланса.

## Повторный пересчёт исходных строк без новых боёв

Оригинальные программы ожидают `battles.jsonl.gz` и сводку в одной папке. `restore-run.cjs` создаёт **только новую папку**, проверяет содержимое `xz`, восстанавливает тот же поток в новый контейнер `gzip` и сохраняет квитанцию. Если сводка содержит `rawSha256`, в её отдельной производной копии меняется только контрольная сумма контейнера; исходный файл пакета, входы, исходы и содержимое строк не меняются.

Пример для подтверждения Громилы:

```sh
review_dir=$(mktemp -d /tmp/seeker-step15-3-review.XXXXXX)
node documentation/raid-redesign-step-15-3-evidence/restore-run.cjs fillers-main-confirmation "$review_dir/main"
node documentation/raid-redesign-step-15-3-evidence/validate-fillers.cjs "$review_dir/main"
```

Для причинных потоков восстановить нужные `ordinary-confirmation`, `causal-screen`, `causal-confirmation`, затем вызвать `validate-causal.cjs` с папкой. Для повторного объединения восстановить первые/последние подтверждения под именами `confirmation` и `independent-confirmation` в общей новой папке; туда же скопировать `causal-screen-validation.json` под именем `broad-validation.json`. Общая папка передаётся `aggregate-two-look.cjs`. Он проверяет входы, объединяет пары и воспроизводит сохранённую поправку на два просмотра. Сам `aggregate.cjs` оставлен исходным и воспроизводит одноразовую производную `causal-aggregate-single-look.json`; основанный на нём помощник двух просмотров добавлен при упаковке, чтобы основной результат тоже пересчитывался одной командой. Вложенные процессы `Node.js` не требуются.

Для широкой матрицы после восстановления `matrix`:

```sh
node documentation/raid-redesign-step-15-3-evidence/analyze-matrix.cjs "$review_dir/matrix" 525 20 3000000000 STEP153_SCREEN
```

Для `ritual-confirmation` соответствующие аргументы — `3 500 3100000000 STEP153_RITUAL_CONFIRMATION`; точное имя фазы сохранено в его оригинальной сводке и командах. `analyze-ritual-inputs.cjs` принимает путь к восстановленному `battles.jsonl.gz`.

Для `analyze-mechanics.cjs` восстановить три подтверждения наполнителей в общей папке с именами `confirm-main`, `confirm-pierce`, `confirm-ritual` и передать общую папку программе. Результат содержит путь рабочей папки, который естественно будет отличаться; сами числовые значения должны совпасть. Никакой пересчёт не требует новых Java-боёв или БД.

Полные команды повторения самих боёв находятся в `causal-commands.md`, `matrix-commands.md`, `ritual-commands.md`, `fillers-*-commands.sh`. `original-classpath.txt` содержит только использованные пути классов/зависимостей, без свойств JVM и настроек приложения; временную ссылку на `classpath.txt` в командах можно заменить этим файлом, а пути адаптировать к своей сборке. При новом исследовании нужны новые выходные папки и явно выбранные начальные значения. Повтор старого потока — проверка воспроизводимости, а не новые независимые наблюдения.
