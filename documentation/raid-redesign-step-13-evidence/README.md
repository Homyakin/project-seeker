## Что сохранено

`baseline.tar.gz` и `baseline.sha256` содержат:

- `baseline/summary.json`, `cases.jsonl.gz`, `battles.jsonl.gz`: 1 264 условия, 20 пар на условие, оба порядка сторон — **50 560 боёв**. Походы — 1 036 условий / 41 440 боёв, аномалии — 228 / 9 120;
- `replay/`: отдельный повтор первой пары каждого условия в новом процессе — **2 528 боёв**, не прибавляемых к основному объёму;
- журналы основного запуска, повтора и 26 модульных тестов, проверку сводок/повторяемости, контрольные суммы 187 отобранных публичных входов и снимок этих файлов;
- отдельные контрольные суммы девяти классов движка, совпавших с принятым движком 12.3; исполнитель не подменяет производственные классы;
- сведения о среде, классовом пути и версиях. Секретный `application-dev.properties`, полный каталог ресурсов, полный каталог `target` и свойства окружения JUnit не включены.

`source/Step13PveBaseline.java` — исследовательский исполнитель, не код рабочей среды. Он вызывает настоящие `RaidGenerator`, `AnomalySafePveGenerator` и `Battle.process` с пределом 2 000 тактов. Сначала создаются новые команды и противники под заданной случайностью генерации, затем бой запускается с отдельным начальным значением. Для обратной стороны всё создаётся заново с теми же исходными значениями.

Корни генерации/боя: `2026110713000` / `3026110713000`; значение равно корню плюс `caseId × 1000 + pair`. Они точно представимы целыми числами JavaScript; пары `0…19` и разные условия не пересекаются. Зеркальные стороны намеренно зависимы. Генерация и бой используют раздельные пространства.

`validate-baseline.cjs` пересчитывает исходы, количества, средние длительности, отношения технической оценки и результаты пар; проверяет составы, старую версию/четыре очка NPC, снятие усиления в аномалиях и одинаковую генерацию зеркальных сторон. С дополнительным аргументом сравнивает все компактные записи первого значения с отдельным повтором. Нельзя выдавать её успешность за проверку целевого V3 против V3.

## Полученные проверки

- Все 50 560 записей согласованы со сводками; ничьих и незавершённых боёв нет, максимум — 133 такта.
- В 36 условиях аномалий с N=2 присутствуют обе ветви 2/3 противника.
- Все 2 528 записей отдельного повтора точно совпали с первым значением основного прогона после нормализации порядка ключей JSON.
- Подтверждены фактические переносы: пращники BACK→FRONT, маггуси MID→FRONT, задние аномалий BACK→MID, средние `ash-wind` MID→FRONT. Это свидетельство текущего недостатка дальности, не будущего исправления.
- `RandomUtilsSeedTest` (2), `Step123ReferenceTeamsTest` (12), `AnomalySafePveGeneratorTest` (7), `WorldRaidPersonageSkillCompatibilityTest` (5): **26/26**, без пропусков, ошибок и нарушений Checkstyle. Это существующие проверки, не проверка будущих адаптированных генераторов.

## Ограничения

20 независимых пар дают точечную консервативную 95-процентную границу около ±30,37 процентного пункта. Это разведка грубых проблем, не точный рейтинг и не одновременная гарантия всей матрицы. Подготовительные запуски не засчитываются как итоговые бои. Новая полная сборка и новая PostgreSQL на этом проектном шаге не выполнялись.

Ступени BEGINNER/MID/STRONG одновременно меняют усиление и модификаторы. Для аномалий усиление снимается; различия ступеней там не доказывают влияние заточки. При изменении N основная команда меняет распределение ролей; это не опыт добавления игрока к неизменному составу. COMMAND_CUIRASS/RITUAL имеют собственное распределение редкости и не объявляются равноценными основным эталонам по цене.

В записи `normalAttacks` используется существующий счётчик `normalAttackCount`, а не сумма всех попыток с промахами. Суммы урона — существующие поля статистики. Золото рассчитано настоящим `RaidRewardGenerator` только для обычных побед/поражений, без истощения, личных/групповых бонусов, предметов и осколков. Для ничьи/незавершения оно не вычисляется. Полная последовательность событий боя не сохранена, только компактные результаты и основы противников.

Все походные эффекты в этом исходном замере пустые. Оба настоящих сервисных пути аномалий и поведение БД при частичном сбое здесь не запускались. Их проверка обязательна далее. Рабочая БД и бот не использовались, настройки не менялись. Постороннее изменение теста блокировок не редактировалось и не включено в снимок.

## Воспроизведение

Фактическая среда: **Axiom JDK 25.0.1**, Maven **3.9.12**, Node **24**; целевая версия Java в POM/компиляции исполнителя — 24. Запуск на JDK 24 не заявляется. Основа — `bd142e61`; после будущей адаптации генераторов требуется историческое дерево этого коммита и сохранённый исполнитель, иначе проверка NPC LEGACY намеренно остановит опыт.

Из `game/` подготовить классы и выполнить затронутые проверки:

```bash
env JAVA_HOME=/home/user/.jdks/axiomjdk-25.0.1 \
  JAVA_TOOL_OPTIONS=-javaagent:/home/user/.m2/repository/org/mockito/mockito-core/5.18.0/mockito-core-5.18.0.jar \
  /opt/apache-maven-3.9.12/bin/mvn test \
  -Dtest=Step123ReferenceTeamsTest,AnomalySafePveGeneratorTest,WorldRaidPersonageSkillCompatibilityTest,RandomUtilsSeedTest
```

Затем из корня проекта, с новым каталогом классов и новым именем каталога результатов:

```bash
step13_classpath=$(sed -n 's/.*<property name="java.class.path" value="\([^"]*\)"\/>.*/\1/p' \
  game/target/surefire-reports/TEST-ru.homyakin.seeker.game.battle.Step123ReferenceTeamsTest.xml)
step13_classes=$(mktemp -d /tmp/seeker-step13-reproduce.XXXXXX)
/home/user/.jdks/axiomjdk-25.0.1/bin/javac --release 24 -cp "$step13_classpath" \
  -d "$step13_classes" documentation/raid-redesign-step-13-evidence/source/Step13PveBaseline.java
/home/user/.jdks/axiomjdk-25.0.1/bin/java -Xmx1g -Dbaseline.pairs=20 \
  -cp "$step13_classes:$step13_classpath" ru.homyakin.seeker.game.battle.Step13PveBaseline \
  "$step13_classes/baseline"
```

Повтор — тот же вызов с `-Dbaseline.pairs=1` и отдельным выходом `replay`. Для проверки распакованных свидетельств:

```bash
/home/user/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node \
  documentation/raid-redesign-step-13-evidence/validate-baseline.cjs /absolute/extracted/baseline /absolute/extracted/replay
```

Сохранённые исходные данные не перезаписывать. Коэффициенты и умения новых противников нельзя подгонять по этим смешанным исходам: после реализации V3 требуется новый исходный замер и проверка затронутых событий.
