`followup` не добавляется к зачтённым 852 080 боям. Его генератор частично переставлял прежние значения, а маг в части опытов находился вне прикрытия. Это записано в основном отчёте. Исходники и данные не исправлялись задним числом. Повторы шести отдельных эпизодов `gap-*` также не являются новыми независимыми наблюдениями.

У каждого набора:

- `*-cases.json.gz` — полные определения команд, предметы, позиции, тактики, назначения, уровни, отключённые умения, число пар и известные составляющие расходов;
- `*-battles.tsv.gz` — исход, начальное значение, порядок сторон, длительность и показатели обеих команд каждого боя; порядок строк зависит от завершения параллельных задач, но ключ `(case, pair, reverse)` однозначен;
- `*-summary.tsv` — отсортированные сводки; `WIN/LOSS` и показатели относятся к канонической левой стороне, `firstSideWinRate` — к первой стороне поля;
- `*-run.properties`, `*-complete.properties`, `*.log` — параметры, завершение и ход выполнения;
- `*-inputs.sha256` — входы относительно `game/` на момент выполнения; `*-sources.jar` — точный проверочный код, обе используемые исходные матрицы и текст политики на тот момент;
- `*-example-*.json.gz` — полные события и подробные записи выбранного затяжного боя в условии, а не только агрегаты.

`gap-tempo3`, `gap-tempo7`, `gap-knockback` и соответствующие `-off` — шесть точных повторов длинных промежутков без атак. Они содержат исходный сценарий, начальное значение, порядок, события и подробные записи. Все показатели сверены с первоначальными строками.

`full-build.log` — итоговая полная сборка текущего стенда: 1 007 тестов учтено, 986 выполнено, 21 пропуск, ноль ошибок. В неё входят 20 новых точных проверок. `targeted-tests.log` — промежуточная проверка до последнего дополнения; её число тестов не подменяет итоговую сборку.

Производственные 1 263 файла всех трёх перечней совпадают. Различия проверочного кода между этапами сохранены в соответствующих архивах. Живой текст политики после закрытия 12.2 может отличаться от снимка; это не изменение проведённого опыта. Старые защищённые свидетельства V4 и mixed-v2 не заменялись и не запускались повторно.

## Повтор текущего подтверждения

Из `game/`, после `mvn clean package`, с JDK 24 или совместимым:

```sh
study_cp=$(sed -n 's/.*<property name="java.class.path" value="\([^"]*\)"\/.*/\1/p' \
  target/surefire-reports/TEST-ru.homyakin.seeker.game.battle.Step12RepresentativeRunnerTest.xml)
java -Xmx2g -cp "$study_cp" \
  -Dstep12.rep.followup=true -Dstep12.rep.seed=2026102303 \
  -Dstep12.rep.iterations=1000 -Dstep12.rep.maxRounds=10000 \
  -Dstep12.rep.output=../documentation/raid-redesign-step-12-2-evidence/recheck-new-name \
  ru.homyakin.seeker.game.battle.Step12RepresentativeSimulator
```

Нужно выбирать **новый выходной префикс**, не пути сохранённых свидетельств. Дополнительный `-Dstep12.rep.filter=...` выбирает условия по регулярному выражению. Для полного воспроизведения старых `primary` и `followup` нужен их архив исходников: нынешний вывод начальных значений намеренно отличается. Отдельный бой можно повторить без восстановления старого генератора через `Step12RepresentativeReplay`, передав сохранённое значение непосредственно.

`outputs.sha256` закрепляет содержимое этой папки; проверка выполняется командой `sha256sum -c outputs.sha256` из неё. Это обычные сохраняемые результаты, не новая одноразовая процедура допуска.
