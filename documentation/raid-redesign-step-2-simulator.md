# Шаг 2. Воспроизводимое моделирование боёв

Дата завершения: 2026-09-01

## Итог

Добавлен воспроизводимый модуль моделирования боёв с управляемым корневым начальным значением генератора псевдослучайных чисел (ГПСЧ), заданным параметром `seed`. Одинаковая версия кода, одинаковые входные параметры и одинаковое значение `seed` дают побайтово одинаковый отчёт в формате `Markdown`. Тяжёлый настроечный прогон не входит в обычный набор `Surefire` и запускается только явно.

Шаг не меняет игровые данные, числовые формулы предметов, параметры походов или награды. Он создаёт измерительный контур для следующих этапов переработки; порядок коллекций, используемых в бою, сделан явным и стабильным ради воспроизводимости.

## Как обеспечивается воспроизводимость

- `RandomUtils.withSeed(seed, action)` создаёт привязанную к текущему потоку область действия ГПСЧ и восстанавливает предыдущую область после завершения или исключения.
- В область с заданным начальным значением включена вся подготовка одного прогона: создание обеих команд, создание похода существующим генератором и сам бой.
- Через управляемый ГПСЧ проходят начальное значение инициативы, перемешивание, выбор цели, критический удар, уклонение, разброс урона, вероятностные умения, нормальное распределение характеристик и случайный тип атаки похода `ZOMBIE_HORDE`.
- Идентификаторы `UUID` участников боя внутри этой области действия создаются воспроизводимо как `UUID` версии 4. В штатном режиме по-прежнему используется `UUID.randomUUID()`.
- Коллекции, чей порядок влияет на бой, переведены на стабильный порядок: линии и живые команды используют `LinkedHashMap`, множество типов атак — `EnumSet`, действующие умения — `EnumMap`, веса целей — `LinkedHashMap`.
- Каждый прогон получает отдельное начальное значение, вычисленное из корневого значения и номера прогона смешиванием `SplitMix64`. Изменение или сбой одного прогона не сдвигает последовательность ГПСЧ следующих прогонов.
- Вне `withSeed` сохранено прежнее случайное поведение штатного режима.

Заданное начальное значение гарантирует повтор результата на одной и той же версии кода. Изменение порядка или количества вызовов ГПСЧ в будущих изменениях кода закономерно может изменить результат при том же значении.

## Состав реализации

- `RandomUtils` — область действия заданного начального значения и воспроизводимые `UUID`.
- `CombatSimulator` — цикл независимых прогонов, сведение результатов и статистика.
- `CombatSimulationRequest` и `CombatSimulationTeams` — описание ячейки, предел числа раундов и способ создавать новые команды для каждого боя.
- `CombatSimulationReport` — структурированный результат и устойчивый формат `Markdown`.
- `RaidSimulationFixtures` — исторические проверочные комплекты из аудита шага 1.
- `RaidCalibrationSimulator` — запускаемый вручную модуль настройки, включаемый системным свойством.
- `RandomUtilsSeedTest`, `BattleDeterminismTest` и `CombatSimulatorTest` — быстрые повторные проверки.

Все классы модуля настройки находятся среди исходных файлов проверок: они доступны проверкам `Maven` и ручному моделированию, но не попадают в основной архив `JAR`.

## Показатели и их смысл

Для каждой ячейки отчёт содержит:

- тип похода, комплект, точный состав, сложность, размер группы, начальное значение ГПСЧ и число боёв;
- максимальное число раундов одного боя;
- долю побед первой, то есть оцениваемой, команды и двусторонний 95-процентный доверительный интервал Уилсона;
- `p50` длительности как медиану и `p95` методом ближайшего ранга;
- среднее число выживших;
- средний остаток здоровья и средний процент остатка здоровья относительно начального максимума команды;
- средние значения фактически нанесённого и полученного урона после учёта снижения, случайного разброса и отсечения урона сверх оставшегося здоровья;
- среднее суммарное число ходов команды.

`Rounds` — такты цикла обработки боя, а `Turns` — реально выполненные действия персонажей. Для полученного урона используется новый доступный только для чтения счётчик фактически потерянного здоровья. Существующий метод `BattlePersonageStats.damageTaken()` намеренно не менялся: его текущая семантика участвует в существующих наградах и должна быть исправлена только отдельным решением.

Нанесённый командой урон вычисляется из фактически полученного урона противоположной команды. Поэтому в показатель входят отложенный урон и урон от эффектов, которые существующий счётчик `skillDamageDealt` не всегда приписывает источнику.

## Исторические проверочные комплекты

| Имя | Позиция | Назначение |
|---|---|---|
| `VIRTUAL_DEFAULT` | `FRONT` | виртуальная стартовая экипировка |
| `PLATE_TANK` | `FRONT` | тяжёлая защита, булава + башенный щит |
| `LEATHER_PIERCE` | `FRONT` | копьё + кинжал |
| `LEATHER_SLASH` | `FRONT` | меч + короткий меч |
| `ARCANE_MAGE` | `BACK` | комплект ткани тайной магии, посох + сфера |
| `CLOTH_MAGE` | `BACK` | обычный тканевый комплект, посох + сфера |

Идентификатор одного комплекта повторяется до размера группы. Смешанный состав задаётся ровно `N` значениями через запятую.

## Запуск

Пример исследовательской ячейки на 1 000 боёв:

```bash
cd game
mvn test \
  -Dtest=RaidCalibrationSimulator \
  -Draid.calibration.enabled=true \
  -Draid.calibration.raidType=MYCONID_COLONY \
  -Draid.calibration.difficulty=10 \
  -Draid.calibration.partySize=3 \
  -Draid.calibration.iterations=1000 \
  -Draid.calibration.maxRounds=10000 \
  -Draid.calibration.seed=20260901 \
  -Draid.calibration.composition=LEATHER_PIERCE,ARCANE_MAGE,PLATE_TANK \
  -Draid.calibration.output=target/raid-calibration-report.md
```

Для приёмки ключевой ячейки меняется только `raid.calibration.iterations=10000`. Ключевые ячейки будут определены после утверждения ролей и эталонных сценариев походов; на этом шаге 10 000 боёв не используются как критерий баланса.

Параметры по умолчанию: `MYCONID_COLONY`, сложность 10, группа из 3 участников, 1 000 прогонов, предел 10 000 раундов, начальное значение `20260901`, комплект `VIRTUAL_DEFAULT`, отчёт `target/raid-calibration-report.md`. Сложность и предел раундов должны быть положительными.

## Проверки

### Автоматические проверки

- `RandomUtilsSeedTest`: все источники случайности, управляемые заданным начальным значением, повторяются; `UUID` имеет версию 4 и вариант `RFC`; вложенная область действия восстанавливается после успеха и исключения.
- `BattleDeterminismTest`: два полных боя похода `ZOMBIE_HORDE` повторяют исходное состояние, варианты неигровых персонажей, журнал действий, исход боя, число раундов и статистику персонажей.
- `CombatSimulatorTest`: повторяются структурированная запись и отчёт в формате `Markdown`; проверены интервал Уилсона, медиана, `p95` методом ближайшего ранга, начальное значение прогона, проверка допустимости, равенство нанесённого и полученного урона между командами и немедленное завершение с ошибкой для боя без возможности завершиться после заданного предела раундов.
- Полный `mvn clean package`: `BUILD SUCCESS`, 365 выполненных проверок, ни одного падения, ни одной ошибки, 19 пропущенных проверок, `Checkstyle` без нарушений.
- В обычном прогоне `Surefire` отсутствует `RaidCalibrationSimulator`; существующий `RaidWinrateTest` остаётся отключённым.

## Ограничения и риски

- Область действия заданного начального значения привязана к текущему потоку выполнения. Она безопасна для независимых параллельных ячеек, но не переносится в задачи, запущенные отдельно внутри этой области.
- Наборы для моделирования обязаны передавать фиксированное время при появлении эффектов, зависящих от времени. Текущее событие похода использует фиксированную дату.
- Существующий генератор похода создаёт служебных персонажей во время расчётов и расходует значения ГПСЧ; это воспроизводимо, но его переработка изменит последовательность результатов.
- Модуль настройки прерывает ячейку с явной ошибкой, если бой достигает предела раундов; частичный результат для боя без возможности завершиться не выдаётся. Существующий основной вызов `Battle.process` сохраняет прежнее поведение без нового ограничения.
- Результаты этого шага нельзя использовать как окончательные целевые показатели баланса до утверждения ролей, системы характеристик и закреплённых наборов для моделирования.
- На шаге 30 тот же измерительный контур расширяется отдельной матрицей боёв против окружения в аномалиях: четыре шаблона, размеры группы `N=1–5`, несколько ступеней экипировки и противодействующие составы. Запрос нового генератора аномалии при этом не получает мощь участников.

## Критерий завершения

Выполнен: одинаковое начальное значение даёт одинаковый структурированный отчёт в формате `Markdown`, включая все источники случайности боя и случайные варианты неигровых персонажей; обычная сборка `Maven` запускает только быстрые проверки и не запускает настроечные серии на 1 000 и 10 000 боёв.
