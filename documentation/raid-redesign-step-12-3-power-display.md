# Шаг 12.3: подготовленная шкала мощи

[← К плану](raid-redesign-plan.md) · [Формула](raid-redesign-step-4-stat-system.md)

Статус: подготовлено к согласованию выпуска, не включено по умолчанию. Новая мощь остаётся только справочным числом: не меняет бой, противников, сложность, доступ, цены и награды. Действующие генераторы противников временно продолжают пользоваться прежним `legacyPower()` до своей переработки в следующих шагах.

## Опорный комплект

Выбран простой полный комплект: меч (`sword`), щит (`shield`), нагрудник (`breastplate`), кожаные шоссы (`leather_chausses`), сапоги (`boots`), кожаный шлем (`leather_helm`) и кожаные перчатки (`leather_gloves`). Все предметы обычные (`COMMON`), усиление `+0`, модификаторов и временных эффектов нет. Заняты все семь ячеек, без пересечений. Это отметка шкалы, а не обещание равной боевой силы или лучший состав текущей меты.

Комплект одинаков в каталогах `SCALING_V3` и подготовленном `SCALING_V4`; локальная доработка церемониальной ткани его не меняет.

| Величина | Значение |
| --- | ---: |
| Здоровье | 2280 |
| Обычная атака на расстоянии 1 | 360 |
| Скорость | 140 |
| Шанс критического удара | 7% |
| Множитель критического удара | 1,36 |
| Уклонение | 15% |
| Кожаная защита | 600 |

Формула шага 4 не меняется: `Мощь = Kмасш × Ж × У`. Умения, угроза, сила воздействия и преимущества расстояния в неё не добавляются.

Средний множитель входящего урона по четырём типам:

```text
M = (500/1040 + 500/1160 + 500/1250 + 500/950) / 4
  = 263329 / 573040

Ж = 2280 / (0,85 × M) ≈ 5837,167685335702
У = 0,14 × (1 + 0,07 × (1,36 − 1)) × 360 = 51,67008
Ж × У = 3068571437568 / 10174075 ≈ 301606,92127471056

Kмасш = 1000 / (Ж × У)
      = 1271759375 / 383571429696
      ≈ 0,00331557377985095
```

В `PowerDisplayVersion.REFERENCE_V1` сохранена именно постоянная дробь масштаба. При запуске она не пересчитывается из текущего каталога: изменение предметов не двигает шкалу незаметно. Изменение формулы или масштаба потребует отдельной версии отображения.

Показывается целое число с округлением к ближайшему (`Math.round` для неотрицательного значения). Поэтому опорный комплект имеет ровно **1000**, а не 10 после дополнительного деления на 100. Выход за поддерживаемый целочисленный диапазон не обрезается молча.

## Подключение и история

`PowerDisplayService` выбирает версию по явному свойству `homyakin.seeker.power-display.version`. Значение по умолчанию — `LEGACY_V1`, сохраняющее прежний вид числа; подготовленное значение — `REFERENCE_V1`. Само добавление кода не включает новый выпуск. Проверка готовности выпуска требует явного согласованного выбора новой шкалы и новых правил боёв.

Профиль, характеристики боя и справочный личный рейтинг получают число из одного вычислителя по постоянным характеристикам экипировки. В локализации оно уже готово к показу и повторно не масштабируется. Приблизительный характер мощи явно поясняется рядом.

Для новых боёв с явно выбранными правилами `SCALING_SKILLS_V2` сохраняется необязательный `PowerDisplaySnapshot`: версия и число, вычисленные по исходной экипировке до временных эффектов и изменений в бою. Снимок находится в уже сохраняемом содержимом `BattlePersonageStats`, отдельная колонка БД не нужна. Старый конструктор статистики сохранён; старые записи без снимка читаются как раньше.

Полные личные отчёты похода, аномалии и мирового похода показывают мощь только из сохранённого снимка и только при включённой соответствующей версии отображения. Текущая экипировка для старого итога не читается. Старые итоги без снимка остаются без числа: восстановить точную исходную экипировку по ним нельзя. Краткие групповые итоги, ранее не показывавшие мощь, не меняются. Синтетические и прежние боевые объекты не получают фиктивного снимка.

Неподдерживаемое для справочной формулы сочетание не должно запрещать проведение боя: для него снимок не создаётся. Прямой запрос новой мощи в профиле проверяет входы и диапазон явно, без подстановки ложного числа.

## Проверки

Добавлены проверки опорной отметки 1000, неизменности её на подготовленном каталоге, обеих версий отображения, округления и переполнения, необязательного снимка, совместимости старого содержимого статистики, сохранения нового снимка и отсутствия повторного масштабирования в локализации. Проверка зависимостей разрешает новые числа только в местах показа, сохранение снимка — в статистике боя, а координатору выпуска — только чтение выбранной версии для проверки готовности.

Результат общей сборки и окончательное решение о включении фиксируются в основном результате 12.3, а не предполагаются этим документом.
